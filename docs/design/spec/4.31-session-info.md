# 4.31 会话信息、请求记录与分享（对话框，S3）

代码 `features/session-info/`，样式 `session-info.css`，文案 `sessionInfo.*`。**不弹 omp 的 `/session`、`/trace`、`/pin`、`/share`、`/retry` 界面**：这五条斜杠命令由 studio 接管（`tsp: "studio"`），数据和动作的取舍见 `docs/architecture/session-history.md` "会话信息"。

**入口**：① 任务菜单（顶栏 `⋯`，`SessionMenu.tsx`；和侧栏任务行的 ⋯ / 右键同一份 `buildTaskMenu`，§4.6）里的会话信息、请求记录、分享链接；② 命令面板：会话信息、请求记录、分享会话链接、置顶 / 取消置顶、重试上一轮（任务空闲时）；③ 斜杠命令 `/session`、`/trace`、`/pin`（切换置顶 + toast）、`/share`、`/retry`。**分享只从这三处进**，会话信息框里没有分享入口（`direction-3.2.md` §2.3：从框里点会在对话框上再叠一个对话框）。

**外壳**：两个框都是 `ui/Dialog`（§4.23）。会话信息框是 lg，两个页签共用这个宽度并有最小高度；分享框是默认的 md。两个框由 `SessionInfoHost.tsx` 挂载，状态在 `session-info-store.ts`（已开着时再打开只切页签）。任务被归档 / 删除时会话信息框自动消失。

## 会话信息框

标题 + 页签条 `ui/Tabs`（概览 `si-tab-info`、请求记录 `si-tab-trace`），没有页脚。读取失败是一条 error `Notice`。

- **概览页**（`si-grid` 两列键值；下面"用量"用同一套网格，两张表的标签对齐）：标题、会话 ID（+ 复制）、会话文件（+ 在文件夹中显示，`revealTaskSession`）、项目目录、工作目录（和项目目录不同时）、Worktree 分支（标签带基分支）、模型（`名称 · provider`，provider 为空时只写名称、不留尾随的 ·）、思考强度（用输入框同一套 `thinkingLabel`）、上下文、开始时间、来自会话（`parentSession`）、额外工作区目录（`additionalDirectories`）。前五项之外没有数据就不画。任务还没有会话文件时只显示任务自己的几行 + 一句说明（`si-no-file`），没有置顶开关和用量。值按首行基线和标签对齐，行内按钮贴着首行。
- **置顶开关**（`si-pin`，`Switch`）：键值表里的一行，没有说明。点击发 `/pin`（切换），之后重读 `session-pins.json`；状态没变就把 omp 的原话当警告 toast，不假装成功。
- **用量与请求**（`si-usage`，标题 `SectionHead`，只靠间距和上面分开）：请求数（`si-requests`）、Token 总数（`si-tokens`，附输入 / 输出 / 缓存读写分项）、缓存命中率（`si-cache-hit`，`composer/usage-format.ts` 的 `cacheHitRate`；分母要加上缓存读写，因为 omp 会话文件 usage 的 `input` 不含它们；缓存读写都是 0 时没有这一行）、费用（`si-cost`，有"没有价格"的请求时注明不含它们）、工具调用数、用过的模型、起止时间。
  - 数据来自 omp 的 `stats.db`（`session_rollup` + `messages`），它**只在 `omp stats` 运行时同步**：打开时先读现有库，同时让 omp 同步一次再重读；底行显示同步中 / 失败原因 / "只统计已同步的部分，可能比输入框里的实时费用略少" + 刷新。库里没有这个会话（`si-no-rollup`）或没有库时各给一句说明。

## 请求记录页

`TraceTab.tsx`。顶行汇总（`trace-summary`：请求 · 失败 · 工具调用 · 费用）+ 刷新；同步失败一条 error `Notice`；没有请求时 `trace-empty`。

- 列表（`trace-list`）的表头（sticky）和每一行共用同一套列：`.si-trace` 是网格，表头 / 条目都是 `subgrid`，列宽只在一处定义，中英文都对齐。
- 每行是紧凑单行（`direction-3.2.md`）：时间（悬停完整时间）、模型（悬停 `provider/model`；子代理请求带类型）、Token 入 / 出（K/M 缩写）、费用、结果（完成 / 调用工具 / 长度截断 / 出错 / 已停止；omp 以后加的取值原样显示）。
- **每行的"详情"默认折叠**（遥测克制）：`ui/Disclosure`（`trace-details-toggle`）在同一行最后一列，`ui/Reveal` 往下展开：耗时、首字耗时、输出速度（studio 按输出 ÷（耗时 − 首字）算，不是 omp 的聚合列）、缓存读写、服务等级、发起的工具调用（出错的标注）、错误信息；都没有时不画"详情"。
- 只显示最近若干条（`src/main/session-info/session-stats.ts` 的 `TRACE_LIMIT`），更早的注明被截掉。

## 分享确认框

`ShareDialog.tsx`（`share-dialog`）。**会把会话上传到外部，必须先确认**（所有者定，2026-10-21）。

- 打开先读 `share.serverUrl` / `share.store` / `share.redactSecrets`（任务目录下 `omp config list --json`，项目配置可覆盖）。
- 正文：① warning `Notice`（`share-warning`）说明会上传加密快照、拿到完整链接的人都能看；勾选 gist 时换成 GitHub secret gist 的说法（`gh` 不可用时 omp 退回上传到服务器）。② 脱敏状态（`share-redact`，`data-redact`）：开着是正常状态不写，关着才提示密钥会原样上传。③ "改为上传到 secret gist" `Checkbox`（`share-gist`，`share.store` 是 gist 时默认勾上）。
- 页脚：取消 / 主按钮**上传并生成链接**（`share-confirm`，设置读到前禁用，上传中 loading）。
- 成功后：正文只有链接（`share-url`，等宽、点一下全选；有 gist 链接时两块各加小标签，第二块 `share-gist-url`），链接折行时平分长度、不折出一个字符的末行。页脚换成在浏览器中打开（`share-open`，只放行 http/https）+ 主按钮复制链接（`share-copy`，拿焦点，Enter 即复制；这一步要做的是复制，关闭靠 × / Esc）。认不出链接时原样显示 omp 的输出（`share-raw`），页脚只有关闭。
- 失败时正文多一条 error `Notice`（`share-error`，`role=alert`，omp 的错误行），可以再试。没有会话文件的任务点分享会失败并说明。

## TSP 错误卡的"重试"按钮

`RetryButton.tsx`（`retry-turn`）：omp 一轮以错误结束时画的错误卡（role `omp.error`）里，对话末尾那张卡（之后没有新消息、没有成功的回答）加一个"重试"，任务空闲时才显示；点击发 `/retry`（`runTaskCommand {kind:"retry"}`）。成功时 omp 不发提示、直接重跑；没有可重试的内容时 omp 的 toast `Nothing to retry` 以错误提示显示。判断在 `src/shared/tsp/error-turn.ts`（`fixtures/tsp/error-turn.jsonl`，omp 18.12.5，无效 key → 401）。

- **错误只显示一份、重试只有一个**：omp 节点里两处和 studio 重复，不画（`isOmpErrorDuplicate`，`TspChildren.tsx`）：dock 里的错误横幅 `omp.errorBanner`（**只在对话里有收尾的错误卡时才不画**，没有卡片时它是这条错误唯一的显示）、错误卡里的 `Retry F5`（`omp.error.action` 且 `actions.click = "retry"`）。卡片里保留复制错误、换模型。键盘 F5 照常（输入框里的 F5 由 studio 转发给 omp）。
- 外观：卡片同出错的过程卡片（淡错误色底、不描边）；"重试"和 omp 的动作排在同一行、重试在最前，omp 的动作画成同高的安静按钮。

## 侧栏的置顶排序

历史会话用 `SessionSummary.pinned`（会话 id 在 omp 的 `<agentDir>/session-pins.json` 里，只读），任务用挂在它上面的那条会话的 `pinned`。置顶的行排在时间线和文件夹里最前面；有置顶行的文件夹排在默认文件夹之后、其余文件夹之前（`sidebar-model.ts`）。置顶只能在有进程的任务里做（`/pin <id>` 在服务进程里报 not found），所以入口只在任务菜单、会话信息、命令面板和 `/pin`，没挂在任务上的历史会话行没有。

## 输入框费用的悬停提示

`SessionCost`：TSP 任务的 token 分项和请求数（`TaskState.sessionUsage.requests`）由主进程从会话文件补（omp 的 TSP 输入框卡片只给费用），见 `tsp-runner` 的 `#sessionUsageFor`；费用或上下文用量变了就重读（只看费用的话，费用一直是 0 时分项永远是 0）。订阅登录的模型 omp 不写 `$`：花费前面是订阅记号（`S0.44`，nerd 字形时是图标），还没花费时只有 `(sub)`（omp 18.12.6 `formatBillingSummary`），`parseCost` 都要认，否则订阅时费用显示 `$0.00`、和用量对话框对不上。
