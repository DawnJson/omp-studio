# 4.2 TaskRow

尺寸、颜色见 `features/sidebar/sidebar.css`；本节只写规则。

- 结构 `[状态槽][标题][尾部]`。任务行和还没挂在任务上的会话行同高、同一套 `.sb-row` 样式，在文件夹里混排（§4.5）。会话没有进程，状态槽只画失败 / 中断（看会话文件里最后一轮的结果，`sidebar-model.ts` 的 `sessionDotKind`、`StatusDot.tsx` 的 `SessionStatusDot`），其余情况不画但留出槽位，让标题和任务行对齐。标题去掉私用区图标字形（`stripIconGlyphs`）。
- 分叉（issue #9）：结构变成 `[状态槽][分叉箭头格][分叉图标][标题][尾部]`，有分叉的行才有箭头格（箭头是 `.sb-row-main` 的兄弟按钮，绝对定位盖在这一格上），分叉行（depth ≥ 1）才有分叉图标；规则见 §4.5“收起分叉”。键盘：Tab 能到箭头，Enter / Space 翻转；行上 `←` 收起、`→` 展开（同文件夹头）。
- 标题单行省略；选中、等待、有未读结果时只换颜色，不换字重。
- 尾部一次只放一个：等待中不放；运行中满一分钟才放 `task.runningFor`（不满时状态点已在转）；`aborted` 放 `task.stopped`；否则相对时间（所有行共用一个时钟）。尾部是固定宽的一列，hover / 键盘聚焦 / 菜单开着时换成 `⋯`（`.sb-row-more`）盖在这一格上；没有尾部的任务行也留着这一格，所以任务行和历史会话行的时间右边对齐。相对时间用 UI 字体 + `tabular-nums`，不用等宽字体：中文会落到回退字体、数字和中文之间空一大格。
- **时间规则**（仓库所有者定，2026-10-20）：时间是任务的最后活动时间，持久化在 `TaskRecord.updatedAt`（`lastActivityAt` 只读它），**只在两种时刻变**：用户发了消息（首条、插话、稍后都算），和一轮结束（完成、失败、中止；两个引擎的 runner 各自在这两处 `#touch`）。选中、恢复、重命名、迁移、存会话文件、采用标题、记模型、归档都不变；`TaskRegistry.updateTask` 不会自动刷新 `updatedAt`，要改只能在 patch 里显式给。从历史会话建的任务，起点是会话文件的修改时间（`ResumeInput.modifiedAt`）。“等你确认”条按 `updatedAt` 从早到晚排。
- 选中：浮起的小卡（底色 + 细描边 + 阴影），不画竖条。改名（F2）时输入框往左伸出内边距 + 描边，框里的字和原来的标题对齐，不跳。
- 重命名：行内 input（`F2` 或菜单），Enter 确认、Esc 取消；存应用元数据（不写 omp）。
- 置顶：会话在 omp 的置顶列表里（`/pin`，`session-pins.json`，和终端版的恢复列表共用）的行，标题后画图钉（`.sb-row-pin`，任务行、会话行都画）。排序见 §4.5。
- 保持运行：标了保持运行的任务行，标题后画闪电（`.sb-row-keep`，和任务菜单"保持运行"同一个图标；会话行没有进程，不画）。
- 菜单只有一份：`features/sidebar/task-menu.tsx` 的 `buildTaskMenu`，侧栏右键、行尾 `⋯`、顶栏任务菜单 `⋯`（§4.6）三个入口共用，项和顺序以代码为准。要点：
  - 置顶走 omp 的 `/pin`，没在跑的任务会先起进程，状态没变时把 omp 的原话当警告显示。保持运行见 `docs/architecture/task-model.md`。会话信息、请求记录、分享见 §4.31。会话树：侧栏里不是当前任务时先选中它。
  - “打开工作目录”（任务 cwd，有 worktree 时是 worktree 根）和“显示会话文件”（`~/.omp/agent/sessions/` 下 omp 的会话记录）是两个地方，分成两项。复制会话 ID / 路径成功 toast `common.copied`（菜单一关就看不到按钮，没有别的反馈）；会话还没有文件 → toast `task.noSession`。导出 HTML 见 `conversation.md`「导出 HTML」。
  - 归档 `Del`：立即从侧栏移除，toast 带撤销。
- 删除会话（issue #10，仓库所有者批准，2026-11-10）：菜单最后一项 `task.delete`（danger），三个入口和会话行菜单（§4.5）都有。点它弹 `ConfirmDialog` danger（`features/sidebar/delete-session.tsx`，焦点在取消）。确认后主进程经 omp 自己的 `/delete` 删会话文件（任务有进程时在它自己的 omp 里发，没有时临时起一个；别的 omp 正开着这个会话时拒绝，`error.sessionInUse`；`docs/architecture/task-model.md`「删除会话」），文件确实没了才去掉任务记录（选中的任务被删时回到新任务草稿）。失败 toast 带 omp 的原话（如 vibe 模式下的 `Exit vibe mode first.`），任务不动。不可撤销。**`Del` 键和输入框 `/delete`（studio 接管，`studio-slash-table.ts`）是归档，不是删除。**
- 标题来源：用户重命名 > omp 记在会话文件里的标题（`title_change`，自动生成或 `/rename`）> 第一条用户消息的首行（折叠空白，截断见代码）。终端标题（OSC 0/2）不当标题：Windows 上伪终端里 cmd、PowerShell 改的控制台标题也会这样发过来（issue #8；`docs/architecture/task-model.md`）。
