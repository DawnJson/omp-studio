# 4.25 ReviewView（全屏评审，阶段 3）

实现在 `features/review/`，样式只用 token（评审专用的有 `--diff-add-bg` / `--diff-del-bg`、`--review-tree-w`、`--rv-no-w`）。

入口：顶栏评审按钮（`topbar-review`，在分支胶囊右边）、提交对话框页脚左侧的 `评审改动`（关掉对话框再打开评审，提交前想看看改了什么）、`Ctrl Shift D`、命令面板 `打开评审`。分支菜单里**不放**评审项（顶栏按钮就在胶囊右边一步到位，菜单只放会改 git 的动作）；输入框上方没有改动条。

盖住顶栏以下的整个窗口（`position: fixed`，层级比输入框栈高一层，输入框不会透出来盖住评审底部；仍低于菜单 / 对话框），淡入，底下的页面 `inert`；`Esc` 或 `退出评审` 关闭，焦点回到触发它的元素（已不在则回输入框）。切到别的任务或任务被删除时自动退出。

- **头**（`rv-head`；3.2 起，`direction-3.2.md` §5）：左起 × 图标按钮（`review-close`，悬停提示 `退出评审`）、标题、分支名（`review-branch`）；右侧依次是视图选项、↻ 刷新（`review-refresh`）、`评论 N`、主按钮 `发给 agent 修改`（`review-send`；队列为空时禁用，发送中 loading；任务在运行时悬停提示说明是插话还是排到本轮之后，取输入框同一个设置 `enterWhileRunning`）。
  - **视图选项**（`ViewControls.tsx`）：宽窗口是两个 `Segmented`——`统一 / 并排` 和 `改动块 / 文件`——加 `折行` 和 `忽略空白` 两个开关图标按钮；窄窗口收进一个 `视图` 菜单按钮（`view-menu`），菜单里同样四项（当前项 ✓）。断点见 `ViewControls.tsx`。统一 / 并排、范围、折行存 `review-store`，会话内记住，关掉评审再打开沿用；`忽略空白` 只存在于这次评审里。
  - **`评论 N`**（`CommentQueue.tsx`，`comment-queue-button`）：没有评论时禁用。点开 `ui/Menu`（`comment-queue`）：每条一项 `文件:行`，第二行是正文开头（评论旧版本时前缀 `旧版本 ·`）；按文件首次出现顺序、文件内按起始行排序（`sortComments`，与发出去的消息一致）。点一项切到那个文件，并把 diff 里对应的行内评论卡滚到中间。
- **两栏**（`direction-3.2.md` §7 第 6 条：评论只留 diff 里的行内卡片，没有右栏）：左 `rv-side` = 文件树 + 提交框；右 diff（`rv-main`）。窄窗口文件树收窄；提交框头部和页脚用 `flex-wrap`，放不下就折行，勾选项文字折行而不是撑出左栏。
  - 文件树：`已暂存 / 未暂存 / 未跟踪` 三组，空组不显示；同一文件两侧都有改动时各出现一次；行 = 状态字母 + 路径 + 行尾 `+a −d`（数字来自主进程一次 `getGitChangeStats`：暂存 / 未暂存各一次 `git diff --numstat`，未跟踪文件直接数行；二进制、过大的文件没有数字）。
  - **提交框**（`CommitBox.tsx`，`review-commit`）：提交信息表单和提交对话框同一份（`features/git/CommitMessageFields.tsx`，testid 前缀 `review-commit-`；仓库所有者定，2026-10-29）：标题 `提交改动` + `已暂存 n 个文件` + `生成` 按钮；摘要 `TextField`、说明 `Textarea`（占位不写"必填""可选"：摘要为空时提交键已禁用）；底行左两个 `Checkbox` `先暂存全部改动`（默认不勾：评审里暂存是显式动作）和 `修改上一次提交`（`review-commit-amend`）、右主按钮 `提交`（勾了 amend 时是 `修改提交`；摘要为空时禁用，提交中 loading）；`Ctrl Enter` 在摘要 / 说明里提交。走和提交对话框同一条路径（`git-actions.ts` 的 `commitChanges` → `commitGit`，提交信息 = 摘要 + 空行 + 说明，`composeCommitMessage`），成功后清空摘要和说明，无论成败都重取状态；失败 / 没有可提交内容走同样的 toast。
    - **生成**（`review-commit-generate`，对话框里 `git-commit-generate`）：让 omp 为已暂存的改动写提交信息——主进程运行 `omp commit --dry-run --no-changelog`（参数数组、不经 shell、cwd = 仓库根；模型由 omp 按它的 `commit` 角色选，studio 不传 `-m`），只把结果填进摘要 / 说明，**不提交**。没有已暂存的改动时灰掉（真实的 omp 在没有暂存内容时会自己 `git add` 全部，所以此时根本不运行它）。进行中按钮 loading（宽度不变），已暂存数的位置换成 quiet `取消`（结束 omp 进程；工具行总在标题下单独一行，生成前后左栏高度不变），评审关掉（提交对话框关掉）也会取消。结果 toast：omp 建议拆成多个提交时只填第一个并提示；没有 commit / smol 模型或 key；其它失败带 omp 的原话（键名见 `git.generate.*`）。已填过内容再点会覆盖。
    - **修改上一次提交**（Amend）：勾上时读出 HEAD 的完整信息（`getLastCommit`）预填摘要 / 说明，按钮变 `修改提交`；取消勾选时，若预填的内容没被改过就还原勾选前输入的内容。上一次提交**已经推送**（`git rev-list -n1 HEAD --not --remotes` 没有输出）时提交前弹 danger `ConfirmDialog`（`review-amend-dialog`，焦点在取消）：改写后哈希变了，普通推送会被远端拒绝，需要强推，而 studio 不提供强推（不改写已推送历史：改写由用户明确确认，studio 自己从不强推）。amend 不要求有暂存内容（只改信息也行）。还没有任何提交时勾选给 toast `git.commit.noPrevious` 并保持不勾。
- **diff**：文件头（路径、`暂存`（已暂存一侧是 `取消暂存`）、`丢弃`（danger））；每个 hunk 一个带边框的块，头部 `@@ … @@` + 区段名 + 该 hunk 的 `暂存 / 取消暂存 / 丢弃`（未跟踪文件没有 hunk 级操作）；当前 hunk 边框高亮。
  - **改动块 / 文件**（默认改动块）：改动块 = 每处改动加 3 行上下文；文件 = 整个文件连成一个 hunk（`getGitFileDiff(…, "file")`），不画 `@@` 头和 hunk 级暂存 / 丢弃（hunk 级操作按 `-U3` 的 header 对账，文件视图里只剩整文件操作），`N / P` 改成在改动块之间走（连续的增删行算一块，当前块第一行描边）。
  - **折行**默认开；关掉后每个 hunk 自己横向滚动（行撑到最长一行那么宽，背景和竖条铺满；评论框和 hunk 头 sticky 贴在可见区左边）。语法高亮复用 Shiki。
  - 统一视图**一列行号**（照 Tern），删除行写旧行号、其余行写新行号（和评论按钮的一侧一致）；新增 / 删除行左缘有绿 / 红竖条（已评论的行在它外面再叠一条 accent 竖条，两条并排不抢位置）；并排视图左旧右新（删除块与新增块逐行配对）。**行号永远显示**，长行折成几行时行号和符号贴着第一行，不在整块的垂直中间（Tern 里 omp 的 diff 也这样）。
  - 二进制、过大、没有文本改动、非 git 仓库、没有 git、没有改动都有各自的一句话状态。
- **丢弃**一律先确认（`ConfirmDialog` danger，`review-discard-dialog`，§4.23），文案说明哪个文件 / 哪处改动、不可撤销（未跟踪或新增的文件写"会被删除"）；确认框放完退出动画才执行丢弃。
- **忽略空白**：会话内有效（评审关掉再打开恢复关闭）。打开后 `getGitFileDiff(…, ignoreWhitespace = true)` 用 `git diff -w`，只改**显示**；按块 / 按行的暂存、取消暂存、丢弃仍是主进程拿不带 `-w` 的 diff 对账，界面上的块和能 `git apply` 的块对不上，所以这时 **hunk 级和行级操作一律禁用**：hunk 头按钮灰掉（原因只在悬停提示 `review.ignoreSpaceBlocked` 里，diff 上方没有常驻说明条），行不可点。整文件的 `暂存 / 取消暂存 / 丢弃` 不受影响，暂存的是完整改动（含被忽略的空白）。
- **按行暂存 / 取消暂存 / 丢弃**（`改动块` 视图、已跟踪的文件、没开忽略空白时）：改动行可点——点一下切换这一行是否选中，Shift 点击从上一次点的行选到这一行（范围里的上下文行跳过），`Shift ↑ / ↓` 从第一个改动行开始逐行扩展（`Esc` 清除）；选中的行高亮。选中后 hunk 头出现 `已选 N 行` + `暂存所选行`（未暂存一侧，还有 danger `丢弃所选行`）/ `取消暂存所选行`（已暂存一侧）+ `清除选择`（testid `lines-*`）；丢弃先确认。主进程生成只含选中行的补丁走 `git apply`（`buildLinePatch`，`docs/architecture/git.md`）。diff 重取（刷新、窗口聚焦、操作之后）后选择作废，行下标不再可信。不能单独应用的选择（文件末尾没有换行的那一行只选了一半）由主进程拒绝并 toast 报错。
- **评论**：行号就是评论按钮（键盘 Tab 可达）；悬停或键盘聚焦时在**行号左边**出现一个 `＋`（绝对定位，不占位），行号本身不动、不变透明，只提亮文字色。不能把 `＋` 和行号叠在同一格里换掉行号：被删除的长行悬停后旧行号列只剩一个 `＋`，看上去像"删除行没有行号"（`test/e2e/review.e2e.ts` 的"删除行的旧行号一直在"钉住）。点一下 = 对这一行评论，Shift 点击把范围扩到这一行（只能在旧或新同一侧内，跨侧则从该行重新开始）。删除行评论旧版本行号，其余评论新版本行号。评论框（`comment-box`）画在范围最后一行下面：`Textarea` + `取消` / `添加评论`（空时禁用；编辑已有评论时是 `保存`），`Ctrl Enter` 提交，`Esc` 只取消评论框。已添加的评论是行下的卡片（`comment-card`；评论旧版本时正文前一枚 `旧版本` 小标签），编辑 / 删除收在右上角 ⋯（`comment-more`）点开的 `ui/Menu` 里：`编辑`、分隔线、红字 `删除`。被评论的行左侧有 accent 竖条。
- **评论队列**：队列在评审关闭后继续保留（同一任务再打开还在），只在发送成功后清空、任务删除时丢弃，不持久化；超过上限（`REVIEW_COMMENTS_MAX`）时不收并 toast `review.queueFull`。`发给 agent 修改`：成功后关闭评审、清空队列、toast；失败保留队列并报错。
- **键盘**（不带修饰键、焦点不在输入框 / 文本域、命令面板没开时生效）：`J / K` 下/上一个文件，`N / P` 下/上一处改动（滚到可见并高亮），`V` 切换统一/并排，`F` 切换改动块/文件，`W` 切换折行，`Esc` 退出（提交框的输入框里不触发；有选中的行时 `Esc` 先清除选择）。`Shift ↑ / ↓` 在改动块视图里选行 / 逐行扩展选择（见"按行暂存"）。`Tab` 序：头 → 文件树 → 提交框 → diff（行号按钮）。
- 数据：状态在打开、窗口重新聚焦、任务状态变化、手动刷新、每次暂存/丢弃之后向主进程重取，diff 和文件树的 `+a −d` 随之重取；不缓存第二份。
- **对标 Tern**（2026-10-21，`tern web serve` + 临时 git 仓库实测）：Tern 的评审是点开分支标签出来的全宽 diff 加右侧文件面板（分组 + `Stage all`、每个文件 `+a −d` 和状态字母、底部提交框 `Summary / Description / Generate message / Amend`），diff 头有 `File / Split / Inline / Hunks` 分段、换行开关、`Stage file`。所有者批准采纳五项（2026-10-21），都已在上面各条：① 文件树每行 `+a −d`（`getGitChangeStats` 一次出所有文件的数，不逐个取 diff）；② 变更行左缘红 / 绿竖条；③ 统一视图一列行号；④ `改动块 / 文件` 视图和折行开关（我们把统一 / 并排和改动块 / 文件拆成两个分段）；⑤ 评审里内嵌提交框（含生成和 Amend）。另采纳行号贴着折行后的第一行。Tern 的评审里没有逐行评论。
- **git 菜单与对话框**（`features/git/`，3.2 起；主进程一侧见 `docs/architecture/git.md`）：
  - 分支胶囊的 Git 菜单（`GitTools.tsx`）是 `ui/Menu` 动作菜单，每项带图标：`提交`、`推送`、`创建 PR`（`canPush` 时才列）；worktree 任务再加 `合并回 <基分支>`、分隔线、最后一项红字 `丢弃 worktree`。不能用的项灰显、不执行，原因写在第二行（如推送：`git.push.noRemote` / `git.push.detached`）。新任务草稿的分支胶囊（`DraftGitTools.tsx`）是选择菜单，只有一项 `在独立 worktree 里开始`，开着时第一列 ✓（`menuitemradio`），不能用时第二行写 `git.draft.blocked`。
  - 对话框（`GitDialogs.tsx`）都是 `ui/Dialog`：**提交**（`git-commit-dialog`）用和评审提交框同一份提交信息表单（仓库所有者定，2026-10-29）：工具行 `已暂存 n 个文件` + `生成`（规则同评审的"生成"，关掉对话框即取消）、摘要（打开时焦点在这里）、说明，`Ctrl Enter` 提交；页脚左侧 `先暂存全部改动`（默认勾）+ `评审改动`（`git-commit-review`，带图标，不然像一句说明文字；关掉对话框并打开评审）；右侧 `取消` / 主按钮 `提交`（摘要为空时禁用）。没有 `修改上一次提交`：入口是 Git 菜单的 `提交` 和 `/git`，都是提交现在的改动，改写上一次提交只在评审里。**创建 PR**（`git-pr-dialog`）= 标题 + 说明，主按钮 `推送并创建`。**丢弃 worktree** = `ConfirmDialog` danger（`git-discard-dialog`，焦点在取消）；正文里分支名用等宽字；确认后对话框先关，丢弃失败由 toast 报错，对话框不再回来。合并冲突、清理无主 worktree 是只有一个主按钮 `关闭` 的列表对话框（`hideClose`，不画右上 ×；文件列表在凹底块里，太长块内滚动）；setup 脚本确认是 sm 对话框（焦点在取消，任何方式关闭都算拒绝）。
