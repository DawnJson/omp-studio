Change` 这类标题和正文同字号同色、只到 `--fw-medium`，比小节标题低一级，2026-10-29），全文显示（同 omp Hub 详情的 Task 字段）；**最终输出**（Markdown，来自 omp 写在会话目录里的 `<名字>.md`；没有输出时整段不画，2026-10-24 起）；**对话记录**（`agents-record`；标题是 `Disclosure`（`agents-record-toggle`），**默认收起**（2026-10-27 仓库所有者：工具调用的细节不默认摆出来；对应 omp Hub 详情里的 Recent activity），点开才读出下面的内容；展开时标题行右端一个 quiet sm `重新读取`（`agents.recordRefresh`）；子代理历史里的工具调用、叙述、思考，读 `<名字>.jsonl`，用 `features/conversation/` 留下的 `buildTurns` + `ProcessDetails` 渲染；运行中每多一次工具调用自动重读，结果还没写进来的那次调用显示转圈 + `Running`、叙述不当结论；2026-10-22）。**插话框**（`agents-steer`）：外观同主输入框（2026-10-27 仓库所有者：原来的 `Textarea` + 文字按钮和主界面不一致）：`.composer` 的框（`--bg-raised` + 1px `--border`、`--radius-composer`、`--shadow-composer`，悬停 / 聚焦边框加深）里一个 `.composer-field` 文本区（`agents-steer-input`，一行起、按内容自动增高到 6 行，占位 `插话，如：先别改测试`，长度上限 `subagentLimits.steerChars`），下面工具行右端是和主输入框同一个圆形发送键（`.send[data-kind="send"]`，`ArrowUp` 16，`agents-steer-send`，悬停提示 / 读屏 `发送`，空文字时禁用）。没有子代理时面板中间显示空状态 `agents.empty`（`--fs-sm` `--text-2`；页签此时不写 0；2026-10-29）。**历史子代理**：同一个 omp 进程里，之前回合的子代理（`done`）一直在列表里；`--resume` 恢复的会话里旧子代理显示为"已挂起"（可恢复，见 `docs/architecture/subagents.md`）。

**操作**（都是主进程在后台驱动 omp 的 Agent Hub，见 `docs/architecture/subagents.md` "后台驱动 Hub"）：**插话**（`SteerBox`：Enter 发送，Shift+Enter 换行，输入法组字时不发；运行 / 等待 / 空闲 / 挂起的子代理才有，已完成 / 被结束 / 失败的没有）、**结束**（运行中才有；omp 自己对 kill 没有确认框，所以点 `结束` 先弹 `Popover` 行内确认（`agents-kill-confirm`，`kind="confirm"`：宽 300、最小 280，右对齐、向下展开）：标题 `结束`、正文 `agents.killConfirm`（`结束 X？它正在做的事会被中止（之后可以恢复）。`），按钮 `不结束`（sm，打开时获得焦点）/ `结束子代理`（danger-solid sm，`agents-kill-yes`））、**恢复**（被结束或挂起的才有）。**驱动期间**（`useTspDrive`，调 IPC 前后）面板顶部出现一条 `agents-driving`（`role="status"`，`data-op` = steer / kill / revive，`data-name`）：`正在发给 Beta…` / `正在结束 Beta…` / `正在恢复 Beta…` （2026-10-24 起没有第二行小字说明）；面板里所有操作按钮和插话框此时停用。**omp 的 Hub 不画出来**（`TspView` 的 layer 区在驱动期间不渲染 picker），过程区压暗且不可点（`.tsp-surface[data-driving]`，`opacity: 0.45`；聚焦模式里过程区暂时是那个子代理的记录，不能当成主对话）；`useTspPanelOpen` 在驱动期间不把这个 Hub 当“面板开着”，主输入框照常可输入——此时发出的消息主进程让它等驱动结束再发到主会话，**不会变成对子代理的插话**。结果用一条 toast（`已发给 Beta` / `已结束 Beta` / `已恢复 Beta`），失败用 `reportOmpError` 带 omp 的原文（例如恢复运行中的子代理时 `Only parked or killed agents can be revived`），插话失败时文字留在框里。

**进入对话（聚焦，2026-10-23；2026-10-26 起只从详情头部进）**：照 omp Agent Hub 里 `Enter` = 聚焦那个子代理的会话。**点列表里的一行只选中它**（详情在列表下方展开，当前详情的行整行高亮，`li.agents-item[data-current]`，同 omp Hub 里移动光标），不切过去（仓库所有者 2026-10-26：点行就跳进对话不对，点"进入对话"才跳）。详情头部（`agents-detail-head`）最左的按钮 `进入对话`（`Button` primary sm，`agents-focus`，之后才是 `结束` / `恢复`）= 聚焦（`focusAgent`，IPC `focusTspSubagent`）：主进程在后台 `agents.open` → `activate`，等聚焦行出现，**不恢复**主输入框（留在聚焦模式）；成功后面板收起（`closeAgentsPanel(false)`，露出过程区）、焦点回 studio 输入框，不弹 toast——输入框上方的聚焦提示（`run-focus`，`正在给 Beta 发消息` + `回到主会话` `run-focus-back`，§4.14）就是反馈和出口；之后输入框发的话走普通 `sendPrompt`（omp 把它 steer 给子代理）。驱动期间沿用 `beginTspDrive` / `endTspDrive`（`agents-driving` 的 `data-op="focus"`，显示 `正在切到 Beta…`，不显示"完成后自动恢复主输入框"那行小字；omp 的 Hub 一帧不画，过程区压暗）。失败（omp 没切过去、行里的子代理 omp 的 Hub 没列出等）：按恢复规则关 Hub，toast 带 omp 的原文，面板留着。**哪些状态有"进入对话"**：`running / idle / parked / aborted`（`canFocus`；实测 omp 18.12.6 的 running 和 aborted（聚焦即复活）能进，见 `docs/architecture/subagents.md`「聚焦」）；`pending`（omp 的 Hub 里还没有这一行，实测聚焦报 `Alpha is not listed in omp's Agent Hub`）和 `done / failed` 没有。聚焦期间 omp 在主界面画的是子代理自己的会话，文档里没有 `agent` 节点（实测），所以面板的列表是空的，面板里什么都不写（原因输入框上方的聚焦提示已经在说）；插话 / 结束 / 恢复此时按「不是文档里的子代理」拒绝，回到主会话后恢复。Activity 页点一行仍是回 Agents 页选中那个子代理（看详情）。

**列表的数据**直接来自 TSP 文档（`shared/tsp/agent-hub.ts` 的 `listAgents`：task 工具卡片下的 `agent` 节点，按名字去重取“更活”的；卡片已结束而节点还写着等待 / 运行的当作挂起），渲染进程用 `useTspDerived` 推导，随 omp 的帧实时更新，**不需要 IPC**；记录和最终输出经 `getTspSubagentRecord(taskId, name)`（主进程只读会话目录里的 `.jsonl` / `.md`，名字限 `isAgentName`、路径必须落在会话目录内，读不到给 `unavailable` + 原因，界面显示原因不吞错）；三个操作经 `steerTspSubagent` / `killTspSubagent` / `reviveTspSubagent`（渲染进程只传任务 id + 名字 + 文字，名字必须是文档里确有的子代理）。

**降级**：omp 改了 Hub 的 role / action 名（`agents.open`、`kill`、`revive`、`omp.composer.focus`、`focus:Main`）时三个操作超时失败，主进程照样走恢复（Esc 关 Hub、退出聚焦），恢复不了才以明确错误抛出；列表、详情、记录不依赖 Hub，不受影响。

**可访问性与动效**：面板 `aria-label`，列表项是真按钮（`aria-current` = 选中），`agents-driving` 是 `role="status"`；驱动横幅的圆点呼吸动画沿用 `--play-state`（减少动效时静止）。

**页签、Activity 页和 Ctx**（2026-10-23，照 omp Agent Hub 的 `1 Agents / 2 Activity` 和 Ctx 列；细节见 `docs/architecture/subagents.md`「Activity 页和 Ctx」）：面板头里的 `ui/Tabs`（`agents-tabs`，2026-10-29 起放进头里，原来是头下面单独一条；`agents.tabAgents`（带个数）/ `agents.tabActivity`；页签状态是面板自己的，关面板后回到 Agents 页）。**Activity 页**（`AgentsActivity`，`agents-activity`）：所有子代理的活动按时间从新到旧排成一条流，数据是详情里"对话记录"本来就在读的 `<名字>.jsonl`（`getTspSubagentRecord`，每个子代理一次，只重读状态或工具调用数变了的；`shared/tsp/agent-activity.ts` 合并，最多 500 条）；顶上一个过滤分段（`Segmented` sm，`agents-activity-filter`，2026-10-29 起，原来是和页签一样的 `Tabs`，两条页签叠在一起像两层导航；`agents.filter.all / errors / responses / tools` = All / Errors / Responses / Tools；testId `agents-activity-filter-<id>`）；每行（`agents-activity-row`，`data-kind` = tool / response / error，`data-agent`，失败的工具调用 `data-failed`）四列：时间（`HH:mm:ss`）、子代理名、种类（`agents.kind.*`）、一行文字（工具名加粗 + intent 或第一个有意义的参数 / 回复第一段 / 错误信息；出错行红字）；点一行 = 回到 Agents 页并选中那个子代理。没有活动时 `agents.activityEmpty`（过滤后没有 `agents.activityNone`，读取中 `agents.activityLoading`）。**Ctx**：`agent` 节点的 `stats.context`（0–1 的占用比例，实测 `0.008099` 配 `contextLabel` `8.1K / 1M`）解析成 `HubAgent.stats.context`；列表行里状态文字左边一个细条 + 百分比（`agents-row-ctx`，`data-percent`，≥ 90% 换错误色，悬停 `agents.contextTitle(Label)`），详情的 Context 统计格显示 `43% · 8.1K / 1M`。
