# 4.22 OmpSetupCard（首次启动与 omp 管理）

`features/omp-setup/OmpSetupView.tsx`，样式 `omp-setup.css`。只在需要用户参与或在等待时出现，omp 就绪后自己淡出。盖住顶栏以下的整个窗口（不透明底），居中一张卡片（`role="dialog"`）；卡片在不透明底上不是浮层，只描边不加阴影。例外是问接管：底下的应用照常画出来、只压一层遮罩，遮罩盖到窗口顶上（含顶栏），顶栏系统三键一起调暗（`ui/title-bar-dim.ts`，§2.1），卡片浮在应用上带阴影。其它状态下顶栏只留标志：任务标题、顶栏工具、侧栏开关 `visibility: hidden`（占位不变；它们作用在还不能用的应用上）。路径放等宽块。

**按钮**（`direction-3.2.md` §2.4）：卡片底部一行右对齐，**次要在前、主按钮在最后**，一张卡最多一个主按钮。

| 状态（`OmpStatus.state`） | 条件 | 内容 | 按钮（左 → 右；★ = 打开时的焦点） |
|---|---|---|---|
| `discovering` | 启动检测 | 一句 `omp.finding` + 转圈（延迟出现，免得一闪而过）；不画卡片：只有一行字的卡片像没内容的对话框 | — |
| `ask_takeover` | PATH 上的 omp 首次发现 | 三种标题和正文：别人管理的（`omp.takeover.other*`）、能启动的自装版（`omp.takeover.exe*`）、`.cmd` 这类脚本（`omp.takeover.title/body`）；Windows 上正文写明会另装一份并改用户 PATH，原来的不动。macOS / Linux 不改 PATH，正文换成 `*StudioOnly` 版（另装一份只给 omp-studio 用，终端里用的不变）。路径块 `omp.takeover.where` / `whereVersion`；不另写"检测到 omp {版本}"：标题已经说了 | ★ 保守的一项（`继续用 {name} 的` / `继续用我的` / `取消`）、主按钮 `由 omp-studio 管理` |
| `missing` | PATH 上没有 omp | `omp.missing.title*` + `omp.missing.body*`；macOS / Linux 换成 `*StudioOnly`（不说加入 PATH） | `我已安装，重新检测`、★ 主按钮 `下载并安装` |
| `installing` | 下载中 | `omp.downloading*` + 进度条 + `omp.progress`；下载完校验时标题换成 `omp.verifying`，进度行和按钮都留着，卡片高度不变、不跳 | `取消下载`（校验中禁用） |
| `unusable` | 拒绝接管，而 PATH 上的是脚本 | `omp.unusable.title` + `omp.takeover.declined` + 路径块 | ★ 主按钮 `重新选择` |
| `error` | 检测、下载、校验、安装、改 PATH 失败 | `omp.error.title` + 一句人话原因（`omp.error.<stage>`；校验失败是 `omp.verifyFailed` + `omp.error.verify`）+ `显示详情`（`ui/Disclosure`，默认收起，展开是原始报错） | `打开设置`（隐藏卡片直到状态再变化，进设置页）、★ 主按钮 `重试` |

没有"连接模型"一步：omp 就绪后直接进 §4.7 新任务草稿页，没有可用模型时见 §4.20 末条。下载由用户点击授权；omp-studio 管理 omp 的细节见 `docs/architecture/omp-install.md`。
