# 4.6 顶栏任务标签与待办板

**任务标签**（所有者定，2026-11-25，方案 A：放在顶栏中段，不多占一行；`features/tabs/`，`task-tabs`，§3.1）：开着的任务各一个标签，从左到右。没有选中任务（新任务草稿）时最右多一个写 `menu.newTask` 的草稿标签（`task-tab-draft`）；末尾一个 `+`（`task-tab-new`，同 `Ctrl N`）。设置页时没有标签是当前的。

- 每个标签（`task-tab`，`data-task-id`）= 状态图标（同侧栏任务行，§4.1；没有图标时不留空位，标题贴左）+ 标题（省略，悬停完整标题）。按钮只在悬停时出来，不进 Tab 顺序：每个标签有 ×（`task-tab-close`），当前标签 × 左边还有重开会话（`task-tab-restart`，不能重开时置灰并写明原因，同下面"重开会话"）。按钮绝对定位盖在标签右端，被盖住的那段标题渐隐（mask）；悬停不改任何尺寸，标签收窄、挤满时也不跳（所有者定，2026-11-25；定宽的做法在挤满时会改掉弹性基准、让标签变宽变窄，e2e"标签挤满收窄时"守着）。当前标签 `--bg-active` 底，别的悬停 `--bg-hover`。放不下时标签先收窄（最窄约 6 个字），再横向滚动（不画滚动条，滚轮可滚），当前标签总滚进视野；标签条只占需要的宽度，其余顶栏空白照样拖动窗口。
- 拖动换位置：标签拖到另一个标签的左半 / 右半，插入线画在那一边（`--accent` 竖线），松手后顺序存进 `ShellState.openTabs`。
- 开：侧栏、命令面板、通知等任何"选中任务"的入口（`selectTask`）都把它加进标签栏（已开就切过去，新的加在最右）；新任务草稿发出第一句话后变成任务标签。
- 关：×、中键点标签、`Ctrl W`、标签上按 `Delete`。**关标签 = 关掉这个任务的 omp 进程**（`closeTask`，任务和对话留着，侧栏里还在，再点开 `--resume` 同一个会话）；任务在跑或在等你确认时先弹确认框（`close-tab-dialog`，"停止并关闭"）。关的是当前标签时切到右边那个，没有就左边那个，都没有回到新任务草稿。任务被归档、删除时标签跟着去掉。
- 右键菜单（`task-tab-menu`）：重命名（标签上就地改，改的是任务标题，同侧栏改名）、颜色一行色板、关闭 / 关闭其他 / 关闭右侧 / 全部关闭（没有可关的那项灰显）。一次关几个时其中有在跑或在等你的，确认框写有几个；关掉的有当前标签就切到它右边最近剩下的，没有就左边，都关了回到新任务草稿。
- 任务颜色（所有者定，2026-11-25，方案 A：左边竖条，标签和侧栏任务行都画）：色板是"无颜色"加主题的 `--chart-1…6`，跟着主题变，不提供自定义取色。设了颜色的标签和侧栏任务行最左画一条 3px 竖条（`TaskColorBar`）。颜色存在外壳状态 `ShellState.taskColors`（`window-state.json`），任务删掉、归档后丢掉。
- **开着标签的任务不关进程**：没有空闲回收、没有进程数上限，也就没有"保持运行"和"关闭会话"（所有者定，2026-11-25；生命周期见 `docs/architecture/task-model.md`）。标签不限个数。
- 切换：点标签；`Ctrl Tab` / `Ctrl Shift Tab` 右 / 左一个，首尾相接；标签上 `← → Home End`（焦点跟着走）。
- 重启恢复：标签列表和当前标签存在外壳状态（`ShellState.openTabs` / `activeTab`，`window-state.json`）。启动后选中上次的当前标签（只有它起 omp 进程），其余标签点到时才起进程。
- 列表规则是纯函数 `features/tabs/task-tabs.ts`（单测 `test/task-tabs.test.ts`），e2e `test/e2e/task-tabs.e2e.ts`。

- **重开会话**：当前标签上的重开按钮、侧栏任务菜单（右键 / 行尾 `⋯`，§4.2）里的 `task.restart`；也可按 `Ctrl Shift R`、命令面板 `task.restart`。动作：主进程结束这个任务的 omp 进程，再用 `--resume=<会话文件>` 起一个新进程（`TaskPool.restartTask`），omp 从会话文件重新载入对话（终端里往同一个会话写的新内容这时才出现），新装的 skill、MCP 服务器、插件和改过的 omp 设置也都重新读取（issue #9；`docs/architecture/session-history.md`）。成功不弹 toast：会话状态变化本身可见。任务在跑、门开着、正在启动、或还有后台作业 / 子代理 / 旁路提问时置灰（`TaskState.restartable` 为 false），写明原因（`task.restartBusy*`），快捷键同样被拒并提示同一句话。
- **顶栏没有任务菜单 `⋯`**：和侧栏任务行的右键 / `⋯` 是同一份菜单，重复了；任务菜单只在侧栏（所有者定，2026-11-25）。
- `TodoBoard`（`features/composer/TodoBoard.tsx`，有 `todoPhases` 时才出现）：输入框正上方状态行（`ComposerTop`，§4.14）右端的一个按钮，照 Tern 里的 omp（omp 18.12.6 实测逐帧对照）：
  - **进度环** `TodoMark state="progress"`：弧从 12 点钟顺时针，弧长正好是 `完成 / 总数`、不夹取（0 是一个圆点，全部完成是整圈）；不转圈，进行中的那项不算半格。后面是当前项文字（窄时隐藏；全部完成时写 `composer.todoAllDone`）+ `{done}/{total}`。全部完成后 omp 过 `tasks.todoClearDelay` 秒自己删掉 HUD 节点，按钮跟着消失。
  - 点击向上弹 popover：阶段（罗马数字编号 + `完成/总数`，图标同 `TodoMark`）与条目（`pending` / `in_progress` / `completed` / `abandoned` 删除线各有标记）。
  - 条目下面一行备注（`todo-note`）；每条右边 ⋯（`todo-item-more`，悬停 / 聚焦 / 菜单开着时显现）弹浮层内嵌的 `MenuList`（`todo-item-menu`：开始 / 完成 / 放弃 / 删除），关浮层时一起收起；已全部完成 / 放弃的阶段默认收起，阶段头是按钮。底栏一行不折行：添加条目（展开一行表单 `todo-add-form`：条目 / 阶段 / 添加）、复制为 Markdown（`todo-copy`，只用图标：带文字时英文窄窗口会把第三个按钮挤到第二行；复制后图标变成对勾，§2.6）、展开全部 / 收起已完成（`todo-expand-all`，有收起的阶段时才显示）。这些动作背后的 `/todo` 子命令和 omp 实测反馈见 `docs/architecture/todo-board.md`。
- **TSP 任务的 `TodoBoard`**：`TaskState.todoPhases` 由主进程从 omp 的 HUD 待办节点（role `omp.hud.todo`，`checklist` 的 `mode:"hud"`）换算（`src/shared/tsp/todos.ts`，`fixtures/tsp/task.jsonl` 逐帧测试，omp 18.12.3）：`active→in_progress`、`done→completed`、`dropped→abandoned`，规范里的 `blocked` 当 `pending`（omp 19.2.1 的待办没有这个状态），阶段标题去掉 omp 加的罗马数字前缀（板自己编号）。测试 id：`tsp-todo-bar`（`.run-todo`）、`todo-board`、`todo-popover`。omp 自己画的 HUD 药丸不画（`TspChildren.tsx`），避免两个入口；工具卡片里的 `omp.tool.todo` 清单仍在过程区里照画。omp 在回合结束清理已完成的待办时板随之收起。`/todo` 由 studio 接管（`tsp:"studio"`）。
- `GoalStrip`（目标模式，`/goal`；`features/goal/GoalStrip.tsx`）：有 `TaskState.goal` 时出现在对话流顶部（TSP 任务里是 `.tsp-view` 的第一个子节点），一行：靶心图标 + 目标文字（省略，悬停完整）+ 状态徽标（只在已暂停、预算用尽时画）+ 已用时间（omp 记录的 `timeUsedSeconds`，为 0 不画）+ 用量（`已用 / 预算`）+ 按钮：进行中 `暂停 / 放弃`、已暂停 `继续 / 放弃`、预算用尽 `放弃`。底色和左边 2px 竖线跟 `.ui-notice` 一样按状态取色：进行中 accent，已暂停 waiting，预算用尽 error（所有者定，2026-11-25：灰底不显眼）。点下后只有被点的那颗 `disabled`；没有自动聚焦。完成或放弃后目标条消失。创建和语义见 `docs/architecture/conversation.md` 的“目标模式”。
  - TSP 任务的 `TaskState.goal` 来自 omp 输入框卡片上的 `Goal …` 行 + 会话文件（`docs/architecture/tsp-migration.md` “目标模式(TSP…)”）；创建 / 暂停 / 继续 / 放弃发 omp 的 `/goal …` 命令，放弃要点掉 omp 的 “Drop goal?” 确认；omp 自己的输入框卡片不画，所以没有重复。目标文字读不到时（会话文件还没落盘且不是 studio 创建的）条上只有“目标 · 状态 · 用量”。
