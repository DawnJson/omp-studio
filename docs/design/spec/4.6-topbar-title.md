# 4.6 顶栏任务标题与待办板

顶栏中段只有任务标题（`app/TaskCrumb.tsx`，`topbar-crumb`，§3.1）：设置页写 `menu.settings`，新任务草稿写 `menu.newTask`，否则是任务标题（悬停提示完整标题）；只显示，不可点。

- **重开会话**：任务标题右边一个 `IconButton`（`topbar-restart`），只在有任务时出现；也可按 `Ctrl Shift R`、命令面板 `task.restart`。动作：主进程结束这个任务的 omp 进程，再用 `--resume=<会话文件>` 起一个新进程（`TaskPool.restartTask`），omp 从会话文件重新载入对话（终端里往同一个会话写的新内容这时才出现），新装的 skill、MCP 服务器、插件和改过的 omp 设置也都重新读取；悬停提示写明这两点（issue #9；`docs/architecture/session-history.md`）。成功不弹 toast：会话状态变化本身可见。任务在跑、门开着、正在启动、或还有后台作业 / 子代理 / 旁路提问时置灰（`TaskState.restartable` 为 false），悬停提示写明原因（`task.restartBusy*`），快捷键同样被拒并提示同一句话。
- **任务菜单 `⋯`**：顶栏任务工具区最右（终端按钮之后、分隔线之前）的 `IconButton`（`task-menu`，`features/session-info/SessionMenu.tsx`），只在对话页且选中了任务时出现；弹出和侧栏同一份 `buildTaskMenu`（§4.2）。“重命名”发 studio 命令 `rename`，在侧栏任务行里就地改名（侧栏收起时先展开）。
- `TodoBoard`（`features/composer/TodoBoard.tsx`，有 `todoPhases` 时才出现）：输入框正上方状态行（`ComposerTop`，§4.14）右端的一个按钮，照 Tern 里的 omp（omp 18.12.6 实测逐帧对照）：
  - **进度环** `TodoMark state="progress"`：弧从 12 点钟顺时针，弧长正好是 `完成 / 总数`、不夹取（0 是一个圆点，全部完成是整圈）；不转圈，进行中的那项不算半格。后面是当前项文字（窄时隐藏；全部完成时写 `composer.todoAllDone`）+ `{done}/{total}`。全部完成后 omp 过 `tasks.todoClearDelay` 秒自己删掉 HUD 节点，按钮跟着消失。
  - 点击向上弹 popover：阶段（罗马数字编号 + `完成/总数`，图标同 `TodoMark`）与条目（`pending` / `in_progress` / `completed` / `blocked` 带原因 / `abandoned` 删除线各有标记）。
  - 条目下面一行备注（`todo-note`）；每条右边 ⋯（`todo-item-more`，悬停 / 聚焦 / 菜单开着时显现）弹浮层内嵌的 `MenuList`（`todo-item-menu`：开始 / 完成 / 放弃 / 删除），关浮层时一起收起；已全部完成 / 放弃的阶段默认收起，阶段头是按钮。底栏一行不折行：添加条目（展开一行表单 `todo-add-form`：条目 / 阶段 / 添加）、复制为 Markdown（`todo-copy`，只用图标：带文字时英文窄窗口会把第三个按钮挤到第二行）、展开全部 / 收起已完成（`todo-expand-all`，有收起的阶段时才显示）。这些动作背后的 `/todo` 子命令和 omp 实测反馈见 `docs/architecture/todo-board.md`。
- **TSP 任务的 `TodoBoard`**：`TaskState.todoPhases` 由主进程从 omp 的 HUD 待办节点（role `omp.hud.todo`，`checklist` 的 `mode:"hud"`）换算（`src/shared/tsp/todos.ts`，`fixtures/tsp/task.jsonl` 逐帧测试，omp 18.12.3）：`active→in_progress`、`done→completed`、`dropped→abandoned`，阶段标题去掉 omp 加的罗马数字前缀（板自己编号）。测试 id：`tsp-todo-bar`（`.run-todo`）、`todo-board`、`todo-popover`。omp 自己画的 HUD 药丸不画（`TspChildren.tsx`），避免两个入口；工具卡片里的 `omp.tool.todo` 清单仍在过程区里照画。omp 在回合结束清理已完成的待办时板随之收起。`/todo` 由 studio 接管（`tsp:"studio"`）。
- `GoalStrip`（目标模式，`/goal`；`features/goal/GoalStrip.tsx`）：有 `TaskState.goal` 时出现在对话流顶部（TSP 任务里是 `.tsp-view` 的第一个子节点），一行：目标文字（省略，悬停完整）+ 状态徽标（只在已暂停、预算用尽时画）+ 用量（`已用 / 预算`）+ 按钮：进行中 `暂停 / 放弃`、已暂停 `继续 / 放弃`、预算用尽 `放弃`。点下后只有被点的那颗 `disabled`；没有自动聚焦。完成或放弃后目标条消失。创建和语义见 `docs/architecture/conversation.md` 的“目标模式”。
  - TSP 任务的 `TaskState.goal` 来自 omp 输入框卡片上的 `Goal …` 行 + 会话文件（`docs/architecture/tsp-migration.md` “目标模式(TSP…)”）；创建 / 暂停 / 继续 / 放弃发 omp 的 `/goal …` 命令，放弃要点掉 omp 的 “Drop goal?” 确认；omp 自己的输入框卡片不画，所以没有重复。目标文字读不到时（会话文件还没落盘且不是 studio 创建的）条上只有“目标 · 状态 · 用量”。
