# 4.27 侧栏文件区 + 右侧预览面板（FilePreviewPane）

**布局**（所有者定，2026-11-24，issue #27，方案 1A + 3A）：文件树在侧栏下半（`SidebarFiles`，`sidebar-files`），预览在主区右侧的预览面板（`file-preview`），面板里一排标签。

**侧栏文件区**：上半是原来的任务列表，下半是当前任务（或新任务草稿）所在项目的文件，中间一条分隔线（`sidebar-files-resizer`，`role="separator"`）可拖动或用 ↑/↓ 调占比，双击回默认（各占一半）；占比范围见 `limits.sidebarFilesShareRange`。头部一行：折叠箭头 + 项目名（`sidebar-files-toggle`，`aria-expanded`，悬停提示项目路径；默认文件夹写 `默认文件夹`）+ 刷新 ↻（`file-tree-refresh`，重读根目录和所有展开的目录，只在展开时有）。收起时只剩这一行，任务列表占满。默认展开；展开 / 收起和占比存在外壳状态（`ShellState.sidebarFilesOpen` / `sidebarFilesShare`，`window-state.json`），所有项目共用一个，重启后保留。根目录跟着当前任务的工作目录（开了 worktree 就是 worktree 目录）；草稿选了项目用项目目录，没选（默认文件夹）用 `AppInfo.chatsDir`（目录第一次发送时才建，没建时显示空目录提示，只读浏览不建目录）。文件区挂在侧栏里，设置等视图下也看得见；点文件时先回对话页。

收起 / 展开：点文件区的标题行，或快捷键 `Ctrl Shift E`（§5.1，对话页）和命令面板的 `文件区`：文件区展开着就收起；否则展开它（侧栏收起或窄窗口抽屉收着时先展开侧栏），焦点进树。顶栏没有文件按钮（所有者定，2026-11-25）。

**右键菜单**：文件树的文件/目录、文件胶囊及对话中的本地文件链接共用原生菜单，仅提供“复制路径”和“在文件管理器中打开”（所有者定，2026-11-16）。复制完整本机路径；文件和目录都在系统文件管理器中定位，不执行文件，也不触发预览、目录展开或新增目录权限。网页链接保留原右键行为。

**文件树**（`file-tree`，`role="tree"`）：只在展开时才向主进程要那一层（`listDirectory(target, relDir)`，见下）：目录在前、文件在后，同类按名字排（不区分大小写，数字按数值）；不列 `.git`；被 `.gitignore` 忽略的条目照列、文字调暗（主进程在该目录里跑 `git check-ignore`，不在仓库里或 git 不可用时没有标记；不隐藏，所以 `node_modules`、`dist` 看得见但不抢眼）；指到根目录外的符号链接和断链不列出。定高虚拟化，只画眼前的行（一层 1500 项也只有几十个 DOM 节点）；名字前是按类型的彩色图标（`ui/FileTypeIcon.tsx`，Material Icon Theme 的图，MIT；文件按文件名 > 扩展名取图，`src`、`docs`、`test` 这类常见文件夹有专属图、展开换打开的样子，认不出的用通用图；预览标签、输入框的文件附件、工具里的文件胶囊用同一套；仓库所有者 2026-11-11 批准）；被忽略的行图标也变淡；名字单行省略、悬停提示相对路径；行贴着侧栏的左右留白、带圆角；预览面板当前标签的文件用中性 `--bg-active` 选中底（所有者定，2026-11-27，与任务列表、子代理列表统一）；光标行（键盘）在树获得焦点时有内描边。一层条目过多时只留排序靠前的，末尾一行截断提示（上限见 `list-directory.ts`）。展开状态、光标行和滚动位置按树根目录记在内存里（同一个文件夹里的任务共用一棵树，切任务时树不重挂、不闪），切走再回来仍在；切回来和点刷新时重读已展开的目录。树不监视磁盘：agent 新建的文件要点刷新才出现。读目录失败（不该发生）走 `reportError` 并收起那个目录。

键盘（树有焦点时）：`↑ ↓` 移动光标，`→` 展开目录 / 已展开则进入第一个子项，`←` 收起 / 回到父目录，`Enter` 或空格 = 文件在预览面板打开、目录展开收起，`Home / End`，`Esc` 关预览面板（没开时交给外层，比如收起抽屉）。点击：目录展开收起，文件在预览面板打开；从树里打开时焦点留在树里，接着挑下一个。

**文件行的 @**（所有者选定，2026-11-24，issue #27）：文件行悬停时（或树有焦点、键盘光标停在这一行时）右端出现 `@` 图标按钮（`file-tree-mention`，悬停提示 `插入到输入框 (@)`，不进 Tab 顺序）；树有焦点时按 `@` 键同样作用于光标行。点了把 `@路径` 插到当前输入框的光标处（选中的文字被替换，前后不是空白就补空格），焦点给输入框，不打开预览；走输入框自己的编辑（`insertAtCaret`），`Ctrl Z` 能撤回。任务目录（草稿是项目目录或默认文件夹）就是 omp 的 cwd，插相对路径；额外工作区目录里的插绝对路径（正斜杠）；路径带空白时写成 `@"…"`。目录、名字里有 `"` 的文件没有这个按钮。

**预览面板**（`file-preview`）：只在对话页、且面板属于当前任务（或当前草稿）时显示；同一时间只有一个右栏面板（预览、子代理、浏览器开一个关另外两个）。默认宽度、最小 / 最大宽度见 `file-preview.css`，左缘可拖动或用 ←/→ 调宽，宽度只存内存；主区（对话 + 输入框）不低于 `--main-min-w`，窗口窄时面板先缩。入口：侧栏文件树点文件；工作记录里工具卡上的文件路径（`FileLink`，`file-link`）和回答里的文件链接；回答里代码块的“在侧栏预览”。头部（`file-preview-head`）：一排标签（`preview-tabs`，`role="tablist"`；放不下时标签先收窄、名字省略，收到最窄还放不下才横向滚动，不画滚动条，竖着的滚轮也横向滚，当前标签总滚进视野）+ 关闭 ×（`file-preview-close`，悬停提示带 `Esc`）。每个标签（`preview-tab`）= 类型图标 + 文件名（片段写 `HTML 片段` 等），悬停提示路径，右边一个 ×（`preview-tab-close`，当前标签和悬停时显示），中键点标签也关。规则（`preview-tabs.ts`，单测 `test/preview-tabs.test.ts`）：再打开已开着的文件 = 切到那个标签；新标签加在最右；最多 `maxPreviewTabs` 个，满了挤掉最久没看的；关当前标签换到右边那个（没有就左边），关掉最后一个 = 关面板。标签按任务 / 草稿记在内存里：关掉面板、切走任务再回来仍在，重开应用就没了；草稿发出第一条消息变成任务后从空开始。键盘：标签上 `← →` 换标签，`Delete` 关当前标签；面板里 `Esc` 关面板，焦点回到打开前的元素。

**预览页**：工具栏（`file-preview-bar`）：类型图标（片段按语言取）+ 文件名 + 路径（和文件名相同时不重复，占满中间的空隙、放不下就省略）；右边一组控件（`file-preview-actions`）按需出现，面板窄得和文件名放不进一行时整组换到第二行、靠右，还放不下就组内再折行（窄窗口下控件不能挤出面板）：

- `渲染 / 源码`（`Segmented`，`file-preview-mode-preview` / `file-preview-mode-source`；只有 Markdown、SVG、HTML 有）；
- HTML 渲染时的 `运行脚本` `Checkbox`；
- 图片渲染时的缩放组：`−` / `+` 夹一个按钮，按钮写 `适应窗口` 或当前百分比，点它回到适应窗口；步长和范围见 `PreviewPage.tsx`；从适应窗口开始缩放时以当时的实际比例为起点（大图适应窗口只有 25% 时点 `−` 是变小不是变大）；放大后按住左键拖动平移，图片不能原生拖出；Ctrl+滚轮同样缩放，每格一步，以指针处为中心；
- 文字缩放：图片以外的内容（文本、Markdown、源码、HTML）用 Ctrl+滚轮整体缩放（CSS `zoom`，iframe 里的网页一起缩放），范围和步长同图片；不是 100% 时才出现一个写当前百分比的按钮，点它回到 100%，没有 `−` / `+`；换文件不复位，面板开着时一直沿用；
- 用系统默认应用打开（`file-preview-open`，`openTaskFile` 白名单里的类型才有）、在文件夹中显示（`file-preview-reveal`，`revealTaskFile`）；这两个只有任务有，草稿里没有。

按类型渲染：`.md` / `.markdown` 渲染 Markdown；图片（png/jpg/gif/webp/svg）用 `<img>` 显示（位图加载主进程登记的 `studio-preview://<token>/`，svg 加载 data URL），适应面板宽度，可缩放，SVG 也只当图片；`.html` 交给主进程登记（`registerHtmlPreview`），`<iframe sandbox>` 加载独立源 `studio-preview://<token>/`，没有 `allow-same-origin`，脚本默认关，勾“运行脚本”才加 `allow-scripts`（换一个 iframe 重新加载），内联脚本能跑、不能联网（外部脚本、图片、字体都加载不了），见 [security.md](../architecture/security.md)「文件预览的网页」；其他文本用 `CodeBlock` 语法高亮整段显示；二进制（开头一段含 NUL）和过大的文件（上限见 `preview-image.ts` / `preview-file.ts`）只给提示和“默认应用打开”，提示在预览区居中；文件不存在只写一句“文件不存在”（文件名工具栏里已有）。

**代码片段**（仓库所有者批准，2026-11-10）：回答里代码块的“在侧栏预览”（§4.10）把这段代码放进预览面板的一个新标签，只在内存里，不写盘（`preview-store.ts` 的 `openSnippetPreview`；标签的 `snippet = { id, kind, code }`，`id` 每打开一段递增，不按内容算，同一段再点也开新标签）；只有 HTML 要经主进程，和网页文件一样登记到主进程内存里给 iframe 加载。标签和工具栏标题是 `preview.snippet`（“HTML 片段”等），没有路径、没有“默认应用打开 / 在文件夹中显示”。渲染走文件的同一条路（`file-preview/snippet.ts` 换成 `PreviewFile`）：HTML 进同一个沙箱 iframe，脚本默认关；SVG 当图片，颜色先按当前主题换（同回答里的 svg 图，切主题重画）；Markdown 用 Markdown 渲染；mermaid 由 `CodeBlock` 画成图（`view` 由 `渲染 / 源码` 控制，代码块头部没有 `<>`）。四种都有 `渲染 / 源码`，换一段回到“渲染”、脚本关。

**指针在不在网页预览上**：网页预览是跨源沙箱 iframe（进程外），指针进了 iframe 后父页面收不到 `pointermove`，`:hover` 也会掉，所以不能用它们判断。Ctrl+滚轮缩放时由主进程读 `screen.getCursorScreenPoint()`，减去 `getContentBounds()`、除以页面缩放换成 CSS 像素，渲染进程用 `elementFromPoint` 判断（`main-window.ts` 的 `zoom-changed`、`PreviewPage.tsx` 的 `onZoomGesture`）。e2e 里 Playwright 的鼠标不动系统光标，要替换 `screen.getCursorScreenPoint`。

主进程：工作区内容经 `readPreviewFile(target, path)` 读，目录经 `listDirectory(target, relDir)` 列，`target` 是 `{ kind: "task", taskId }`、`{ kind: "project", projectId }` 或 `{ kind: "defaultFolder" }`（渲染进程不传根路径，由主进程按 id 查；`defaultFolder` 不带任何字段，主进程自己取 `chatsDir()`，`@` 补全用同一个 target，默认文件夹的草稿里也能用）。相对路径按根目录解析，落在根内的绝对路径先换成相对路径，越界（绝对路径、`..`、符号链接解析后在根外，`resolveInsideReal` / `listDirectory` 的 realpath 校验）拒绝；读文件不存在返回 `missing`，列目录不存在返回空列表，`@` 补全根目录不存在时没有候选（`@` 补全不收名字里有空白的文件）。网页预览（文件和 HTML 片段）经 `registerHtmlPreview(html)` 换一个 token（上限 `limits.htmlPreviewMaxChars`），内容换了、预览卸载时 `releaseHtmlPreview(token)`；主窗口重载或关闭时主进程全部清掉。实现在 `features/file-preview/`（`SidebarFiles` 侧栏文件区、`FileTree` + `tree-model.ts` 纯逻辑、`FilePreviewPane` 面板外壳和标签、`preview-store.ts` + `preview-tabs.ts` 标签状态、`PreviewPage`/`PreviewContent`）与 `src/main/files/`（`list-directory.ts`、`preview-file.ts`）、`src/main/ipc/file-handlers.ts`（`parseFilesTarget` / `targetCwd`）、`src/main/ipc/preview-handlers.ts` + `src/main/window/preview-protocol.ts`（网页预览）。参照说明：Tern 的命令行帮助里只有 `tern open [--preview] PATH`（在标签页旁开文件块），没有文件树（只查了 `tern help` / `tern open --help`），所以树的交互参照常见编辑器的资源管理器。

**工作区目录（`/add-dir`；只有任务有，草稿没有）**：侧栏文件区头部下面一行（`workspace-roots`，`file-preview-roots`，窄时折行）：有额外目录时先是一枚 `任务目录`（`workspace-root-0`）和每个额外目录一枚胶囊（`workspace-root-<n>`，显示目录名、悬停提示完整路径，`aria-pressed` = 树当前看的根）+ 紧挨着的 ×（`workspace-root-remove-<n>`，悬停提示“从工作区移除：{path}”），胶囊、× 和添加按钮同高；行尾总有 `添加文件夹…`（`Button` quiet sm，`workspace-add-dir`）。有额外目录时整行的悬停提示 `preview.dirsNote`：额外目录只在这次运行里有效（实测 omp 不把它们写进配置，进程退出就没了，所以列表随进程清空，树里选的根落回任务目录）。点胶囊 = 树换成那个根（展开状态、光标、滚动位置按根目录分别记）；预览标签记着打开文件时的那个根（`PreviewTab.root`），切根不会让预览读错目录。`添加文件夹…`：主进程弹系统文件夹选择框（`addWorkspaceDir(taskId)`，渲染进程不传路径），选中后在这个任务自己的 omp 里执行 `/add-dir <路径>`，成功后选中新根并弹一条 toast；取消什么都不做；omp 拒绝（目录不存在、已在工作区）时错误 toast 显示 omp 原文（`reportError`）。× = `removeWorkspaceDir(taskId, 下标)`，主进程按它记的列表取路径执行 `/remove-dir`，成功后如果正看着这个根就回任务目录。执行期间 `添加文件夹…` 和各个 × 禁用。命令走 `TspRunner.runSessionCommand`：没有进程时先启动 omp，在任务的界面操作队列里串行执行，不等这一轮结束；有审批或提问在等、或 omp 的面板开着时立刻 reject（`#awaitComposer`），同样是错误 toast。斜杠命令是快捷入口（`tsp: "studio"`，`features/file-preview/dirs-slash.ts`）：`/dirs` 向 omp 重新问一次列表并展开侧栏文件区；`/add-dir` 不带路径弹选择框、带路径把用户输入的整行交给 omp（相对路径按任务目录解析）；`/remove-dir` 不带路径只展开文件区、带路径执行。

数据流：`TaskState.workspaceDirs`（额外目录，不含任务 cwd，按 omp 给的顺序）只来自 omp 的输出——`/dirs`、`/add-dir`、`/remove-dir` 的状态 toast（`omp.toast.status`），解析在 `src/shared/omp-output/dirs.ts`（`parseDirsOutput`，用 omp 18.12.5 实测原文写单测）；主进程 `tasks/workspace-dirs.ts` 记最近一次的列表，`TaskPool.runWorkspaceDirsCommand` 执行并更新，解析不了或 omp 拒绝时以 omp 原文 reject、列表不变。命令文本由封闭的 `TaskCommand`（`addDir` / `removeDir` / `dirs`）拼，路径是命令名后面的整行，**绝不加引号**（实测引号会被当成路径的一部分），含换行 / 控制字符的路径被拒绝。

**工作区路径校验：在任务目录内，或在这个任务的某个工作区目录内**（所有者定，2026-10-21）。渲染进程只能用整数下标选根：`ProjectFilesTarget` 的 `{ kind: "task", taskId, root? }`（`root` 缺省 / 0 = 任务 cwd，n = 第 n 个额外目录，`parseFilesTarget` 校验范围；别的 kind 的 `root` 被丢掉），`openTaskFile` / `revealTaskFile` 的第三个参数同理；绝对根路径由主进程从自己记的 omp 列表里按下标取（`files/task-roots.ts` 的 `rootDir`）。选定根之后，相对路径、根内绝对路径和符号链接解析后的实际路径必须仍在**那个根**内。未指定额外根的任务绝对文件链接，由主进程在已授权根中自动匹配；打开和定位保留原绝对路径，下标被移除或重用时拒绝打开其他目录的同名文件。`@` 补全仍只在任务 cwd 里找。

**文件链接直接预览**：点击本机文件链接直接展示内容，包括工作区外的文件，不显示授权或文件选择框（所有者定，2026-11-16）；工作区外的文件只读，预览工具栏不显示系统打开和定位。读取规则见 `docs/architecture/file-preview.md`。
