# 4.27 FilePreviewPane（右侧文件面板：文件树 + 预览，照 Tern 里 omp 点文件 chip 的侧栏）

入口两个：① 工作记录里工具卡上的文件路径（`FileLink`，`file-link`，显示文件名，完整路径在悬停提示里）直接打开**预览页**；② 顶栏右侧工具区的“文件面板”按钮（`topbar-files`，在分支/评审之后、终端之前，`aria-pressed` = 当前任务的面板开着）、快捷键 `Ctrl Shift E`（§5.1）和命令面板的 `文件面板`，打开**文件页**，再按一次关闭。新任务草稿也有：选了项目时根目录是项目目录，没选项目（默认文件夹）时根目录是 `AppInfo.chatsDir`（目录第一次发送时才建，没建时文件页显示空目录提示，只读浏览不建目录）。面板开合状态按任务 / 草稿各记各的（草稿发出第一条消息后变成任务，那个任务的面板是关着的）。主区右侧打开面板（`file-preview`，默认宽度、最小 / 最大宽度见 `file-preview.css`，左缘可拖动或用 ←/→ 调宽，宽度只存内存），主区（对话 + 输入框）不低于 `--main-min-w`，窗口窄时面板先缩，输入框工具行不会被挤成多行；同一时间只有一个面板；只在对话页、且面板属于当前任务（或当前草稿）时显示。

头部（`file-preview-head`）：左边顶层页签 `ui/Tabs` `文件 | 预览`（`file-preview-page-files` / `file-preview-page-preview`；没打开过文件时“预览”页签禁用），右边是文件页才有的刷新 ↻（`file-tree-refresh`，重读根目录和所有展开的目录）+ 关闭 ×（`file-preview-close`，关的是整个面板，悬停提示带 `Esc`）。两页同时挂载、切页只是显隐，所以树的滚动位置和已加载的目录不丢。

**文件页**（`file-tree`，`role="tree"`）：根目录跟着任务的工作目录（开了 worktree 就是 worktree 目录），草稿用草稿的项目目录。只在展开时才向主进程要那一层（`listDirectory(target, relDir)`，见下）：目录在前、文件在后，同类按名字排（不区分大小写，数字按数值）；不列 `.git`；被 `.gitignore` 忽略的条目照列、文字调暗（主进程在该目录里跑 `git check-ignore`，不在仓库里或 git 不可用时没有标记；不隐藏，所以 `node_modules`、`dist` 看得见但不抢眼）；指到根目录外的符号链接和断链不列出。定高虚拟化，只画眼前的行（一层 1500 项也只有几十个 DOM 节点）；名字前是按类型的彩色图标（`ui/FileTypeIcon.tsx`，Material Icon Theme 的图，MIT；文件按文件名 > 扩展名取图，`src`、`docs`、`test` 这类常见文件夹有专属图、展开换打开的样子，认不出的用通用图；预览页标题、输入框的文件附件、工具里的文件胶囊用同一套；仓库所有者 2026-11-11 批准）；被忽略的行图标也变淡；名字单行省略、悬停提示相对路径；行左右各缩进一点、带圆角（同子代理列表的行：选中、悬停、键盘光标不顶到面板的圆角描边）；正在预览的文件有强调底；光标行（键盘）在树获得焦点时有内描边。一层条目过多时只留排序靠前的，末尾一行截断提示（上限见 `list-directory.ts`）。展开状态、光标行和滚动位置按任务（或草稿）记在内存里，关掉面板、切走任务再回来仍在；切回文件页和点刷新时重读已展开的目录。读目录失败（不该发生）走 `reportError` 并收起那个目录。

键盘（树有焦点时；打开文件页时焦点自动进树）：`↑ ↓` 移动光标，`→` 展开目录 / 已展开则进入第一个子项，`←` 收起 / 回到父目录，`Enter` 或空格 = 文件打开预览（切到预览页）、目录展开收起，`Home / End`，`Esc` 关闭面板。点击：目录展开收起，文件在同一面板里切到预览页。

**预览页**：工具栏（`file-preview-bar`）：类型图标（片段按语言取）+ 文件名 + 路径（和文件名相同时不重复，占满中间的空隙、放不下就省略）；右边一组控件（`file-preview-actions`）按需出现，面板窄得和文件名放不进一行时整组换到第二行、靠右，还放不下就组内再折行（窄窗口下控件不能挤出面板）：

- `渲染 / 源码`（`Segmented`，`file-preview-mode-preview` / `file-preview-mode-source`；只有 Markdown、SVG、HTML 有）；
- HTML 渲染时的 `运行脚本` `Checkbox`；
- 图片渲染时的缩放组：`−` / `+` 夹一个按钮，按钮写 `适应窗口` 或当前百分比，点它回到适应窗口；步长和范围见 `PreviewPage.tsx`；从适应窗口开始缩放时以当时的实际比例为起点（大图适应窗口只有 25% 时点 `−` 是变小不是变大）；放大后按住左键拖动平移，图片不能原生拖出；Ctrl+滚轮同样缩放，每格一步，以指针处为中心；
- 文字缩放：图片以外的内容（文本、Markdown、源码、HTML）用 Ctrl+滚轮整体缩放（CSS `zoom`，iframe 里的网页一起缩放），范围和步长同图片；不是 100% 时才出现一个写当前百分比的按钮，点它回到 100%，没有 `−` / `+`；换文件不复位，面板开着时一直沿用；
- 用系统默认应用打开（`file-preview-open`，`openTaskFile` 白名单里的类型才有）、在文件夹中显示（`file-preview-reveal`，`revealTaskFile`）；这两个只有任务有，草稿里没有。

按类型渲染：`.md` / `.markdown` 渲染 Markdown；图片（png/jpg/gif/webp/svg）用 `<img>` 加载 data URL，适应面板宽度，可缩放，SVG 也只当图片；`.html` 交给主进程登记（`registerHtmlPreview`），`<iframe sandbox>` 加载独立源 `studio-preview://<token>/`，没有 `allow-same-origin`，脚本默认关，勾“运行脚本”才加 `allow-scripts`（换一个 iframe 重新加载），内联脚本能跑、不能联网（外部脚本、图片、字体都加载不了），见 [security.md](../architecture/security.md)「文件预览的网页」；其他文本用 `CodeBlock` 语法高亮整段显示；二进制（开头一段含 NUL）和过大的文件（上限见 `preview-file.ts`）只给提示和“默认应用打开”，提示在预览区居中；文件不存在只写一句“文件不存在”（文件名工具栏里已有）。

**代码片段**（仓库所有者批准，2026-11-10）：回答里代码块的“在侧栏预览”（§4.10）把这段代码放进同一个预览页，只在内存里，不写盘（`preview-store.ts` 的 `openSnippetPreview`，`PanelState.snippet = { id, kind, code }`，和 `path` 二选一；`id` 每打开一段递增，不按内容算）；只有 HTML 要经主进程，和网页文件一样登记到主进程内存里给 iframe 加载。工具栏标题是 `preview.snippet`（“HTML 片段”等），没有路径、没有“默认应用打开 / 在文件夹中显示”。渲染走文件的同一条路（`file-preview/snippet.ts` 换成 `PreviewFile`）：HTML 进同一个沙箱 iframe，脚本默认关；SVG 当图片，颜色先按当前主题换（同回答里的 svg 图，切主题重画）；Markdown 用 Markdown 渲染；mermaid 由 `CodeBlock` 画成图（`view` 由 `渲染 / 源码` 控制，代码块头部没有 `<>`）。四种都有 `渲染 / 源码`，换一段回到“渲染”、脚本关。“预览”页签在有片段时可点；文件页里点文件 = 换回文件预览，片段丢掉。

**指针在不在网页预览上**：网页预览是跨源沙箱 iframe（进程外），指针进了 iframe 后父页面收不到 `pointermove`，`:hover` 也会掉，所以不能用它们判断。Ctrl+滚轮缩放时由主进程读 `screen.getCursorScreenPoint()`，减去 `getContentBounds()`、除以页面缩放换成 CSS 像素，渲染进程用 `elementFromPoint` 判断（`main-window.ts` 的 `zoom-changed`、`PreviewPage.tsx` 的 `onZoomGesture`）。e2e 里 Playwright 的鼠标不动系统光标，要替换 `screen.getCursorScreenPoint`。

主进程：内容一律经 `readPreviewFile(target, path)` 读，目录经 `listDirectory(target, relDir)` 列，`target` 是 `{ kind: "task", taskId }`、`{ kind: "project", projectId }` 或 `{ kind: "defaultFolder" }`（渲染进程不传根路径，由主进程按 id 查；`defaultFolder` 不带任何字段，主进程自己取 `chatsDir()`，`@` 补全用同一个 target，默认文件夹的草稿里也能用）。相对路径按根目录解析，落在根内的绝对路径先换成相对路径，越界（绝对路径、`..`、符号链接解析后在根外，`resolveInsideReal` / `listDirectory` 的 realpath 校验）拒绝；读文件不存在返回 `missing`，列目录不存在返回空列表，`@` 补全根目录不存在时没有候选（`@` 补全不收名字里有空白的文件）。网页预览（文件和 HTML 片段）经 `registerHtmlPreview(html)` 换一个 token（上限 `limits.htmlPreviewMaxChars`），内容换了、预览卸载时 `releaseHtmlPreview(token)`；主窗口重载或关闭时主进程全部清掉。打开面板时焦点进面板（预览页）或进树（文件页），Esc 或 × 关闭并把焦点还给打开前的元素。实现在 `features/file-preview/`（`FilePreviewPane` 外壳、`FileTree` + `tree-model.ts` 纯逻辑、`PreviewPage`/`PreviewContent`）与 `src/main/files/`（`list-directory.ts`、`preview-file.ts`）、`src/main/ipc/file-handlers.ts`（`parseFilesTarget` / `targetCwd`）、`src/main/ipc/preview-handlers.ts` + `src/main/window/preview-protocol.ts`（网页预览）。参照说明：Tern 的命令行帮助里只有 `tern open [--preview] PATH`（在标签页旁开文件块），没有文件树（只查了 `tern help` / `tern open --help`），所以树的交互参照常见编辑器的资源管理器。

**工作区目录（`/add-dir`；只有任务有，草稿没有）**：文件页头部下面一行（`workspace-roots`，`file-preview-roots`，窄时折行）：有额外目录时先是一枚 `任务目录`（`workspace-root-0`）和每个额外目录一枚胶囊（`workspace-root-<n>`，显示目录名、悬停提示完整路径，`aria-pressed` = 树当前看的根）+ 紧挨着的 ×（`workspace-root-remove-<n>`，悬停提示“从工作区移除：{path}”），胶囊、× 和添加按钮同高；行尾总有 `添加文件夹…`（`Button` quiet sm，`workspace-add-dir`）。有额外目录时整行的悬停提示 `preview.dirsNote`：额外目录只在这次运行里有效（实测 omp 不把它们写进配置，进程退出就没了，所以列表随进程清空，树里选的根落回任务目录）。点胶囊 = 树换成那个根（展开状态、光标、滚动位置按“任务 + 根”分别记）；预览页看的是打开文件时的那个根（`PanelState.root`），切根不会让预览读错目录。`添加文件夹…`：主进程弹系统文件夹选择框（`addWorkspaceDir(taskId)`，渲染进程不传路径），选中后在这个任务自己的 omp 里执行 `/add-dir <路径>`，成功后选中新根并弹一条 toast；取消什么都不做；omp 拒绝（目录不存在、已在工作区）时错误 toast 显示 omp 原文（`reportError`）。× = `removeWorkspaceDir(taskId, 下标)`，主进程按它记的列表取路径执行 `/remove-dir`，成功后如果正看着这个根就回任务目录。执行期间 `添加文件夹…` 和各个 × 禁用。命令走 `TspRunner.runSessionCommand`：没有进程时先启动 omp，在任务的界面操作队列里串行执行，不等这一轮结束；有审批或提问在等、或 omp 的面板开着时立刻 reject（`#awaitComposer`），同样是错误 toast。斜杠命令是快捷入口（`tsp: "studio"`，`features/file-preview/dirs-slash.ts`）：`/dirs` 向 omp 重新问一次列表并打开文件页；`/add-dir` 不带路径弹选择框、带路径把用户输入的整行交给 omp（相对路径按任务目录解析）；`/remove-dir` 不带路径只打开文件页、带路径执行。

数据流：`TaskState.workspaceDirs`（额外目录，不含任务 cwd，按 omp 给的顺序）只来自 omp 的输出——`/dirs`、`/add-dir`、`/remove-dir` 的状态 toast（`omp.toast.status`），解析在 `src/shared/omp-output/dirs.ts`（`parseDirsOutput`，用 omp 18.12.5 实测原文写单测）；主进程 `tasks/workspace-dirs.ts` 记最近一次的列表，`TaskPool.runWorkspaceDirsCommand` 执行并更新，解析不了或 omp 拒绝时以 omp 原文 reject、列表不变。命令文本由封闭的 `TaskCommand`（`addDir` / `removeDir` / `dirs`）拼，路径是命令名后面的整行，**绝不加引号**（实测引号会被当成路径的一部分），含换行 / 控制字符的路径被拒绝。

**路径校验：在任务目录内，或在这个任务的某个工作区目录内**（所有者定，2026-10-21）。渲染进程只能用整数下标选根：`ProjectFilesTarget` 的 `{ kind: "task", taskId, root? }`（`root` 缺省 / 0 = 任务 cwd，n = 第 n 个额外目录，`parseFilesTarget` 校验范围；别的 kind 的 `root` 被丢掉），`openTaskFile` / `revealTaskFile` 的第三个参数同理；绝对根路径由主进程从自己记的 omp 列表里按下标取（`files/task-roots.ts` 的 `rootDir`），下标过期（目录刚被移除）直接 reject，不会落到别的根。选定根之后照常校验：相对路径、`..`、符号链接解析后（`resolveInsideReal` / `listDirectory` 的 realpath）必须在**那个根**内——额外目录里的链接指向任务目录或别的地方同样被拒绝。`@` 补全只在任务 cwd 里找（不扫额外目录）；工具卡上的文件链接按任务 cwd 解析，落在额外目录里的绝对路径不会被换算。
