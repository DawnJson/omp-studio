# 4.17 门（omp 的审批卡与提问对话框）

门是 omp 在 dock 里画的 TSP 节点，studio 照画（`features/tsp/`），不自绘门，也不本地化门里的文字。dock 紧跟在对话后面：对话短时就在最后一项下面，对话长过视口时停在过程区底部、studio 输入框正上方（仓库所有者定，2026-10-29）；宽同对话列（§4.14“输入框与过程区的分工”）。门不是模态，对话照常可读、可滚动。dock 最多占满过程区，再高时 dock 自己滚动，方向键选到看不见的选项时滚进视野。

- **提问文本框的按键**：输入、退格、Delete 和选区操作由文本框处理，外层选项列表不再转发；焦点在列表本身时，数字选项和方向键照常工作。

| 门 | 节点（role） | studio 输入框 |
|---|---|---|
| 审批 | `omp.editor.ask.approval`：插在 omp 的输入框卡片（`omp.editor`，studio 不画）前面；标题（如 `Allow tool: bash`，右端 Details 按钮；用正文色加粗，不用 omp 给的强调色）、命令详情、选项 `list`（Approve / Approve bash for this session / Deny，单击即提交，omp 18.12.6 实测见 `docs/architecture/tsp-real-omp-probes.md` §18）；omp 底栏的 Deny / Approve 按钮不画（`gate.ts` 的 `isApprovalDuplicateButton`），和选项重复 | 照常能发。有草稿时 `Enter` = 拒绝待批的调用，并把这句话作为插话交给 omp；空草稿 `Enter` 不动作；`Ctrl+Enter` = 批准；`Ctrl+O` = Details。占位符 `composer.placeholderGate` |
| 提问 | `omp.editor.ask`：把 omp 的输入框卡片整个换掉；问题 `md`、选项 `list`、“其他”输入；多题时有页签和 Review 页；底栏 Hide / Note / Skip / Next（最后是 Submit）。对话框开着时，对话里那张提问工具卡（`omp.tool.ask`）头上不写题目（和对话框标题重复；仓库所有者定，2026-10-29），对话框隐藏（`omp.editor.ask.hidden`）或答完后照常写；对应哪张卡片由 `shared/tsp/ask-gate.ts` 的 `openAskTool` 判断 | 不能发：发送键禁用，`Enter` 不发，占位符 `composer.placeholderAsk`。在提问对话框里回答 |

- **判断集中在 `src/shared/tsp/gate.ts`**，主进程 `TspRunner` 和渲染进程 `Composer.tsx` 共用：`findMessageTarget` 返回 `ready`（`approval: true` = 有审批在等）、`ask`、`panel`（omp 的全屏面板或 Agent Hub 开着）或 `pending`；`findGateButton` 找审批卡上的 approve / expand 按钮。role 和动作名是 omp 自己的，不在 TSP 规范里，omp 改名这条规则就失效。
- **任务状态**：dock 里有 role 以 `omp.editor.ask` 开头的节点 = `needs_you`（`shared/tsp/task-status.ts`）。主进程为它合成一个 `TaskState.dialogs[0]`（`kind: "confirm"`，id `tsp-approval` / `tsp-ask`），给侧栏的等你提示条、托盘和系统通知（§5.7）用；输入框也按这个 id 区分审批和提问。同一时刻 dock 里只有 omp 画的那一个门，studio 不另外排队。
- **拒绝并发送**是普通的 `send`，不另发 deny：omp 收到消息就拒绝待批的调用，并把消息作为插话交给模型（`omp://approval-mode.md`；omp 18.12.5 实测，`tsp-real-omp-probes.md` §14）。批准和 Details 是对审批卡上对应按钮发 `action` 事件，和鼠标点按钮是同一个事件。键位在 `composer/send-logic.ts` 的 `decideEnter`。
- **审批期间不做的事**：切模型、切思考强度、studio 代发的斜杠命令（`runTaskCommand`、`/fast`、`/slow` 等）立刻 reject（`composer_unavailable`），否则它们的 `send` 会顺手拒掉审批（`TspRunner.#awaitComposer`）。
- **焦点**：门里的选项 `list`（`interactive/List.tsx`）和提问对话框根节点（`interactive/AskGate.tsx`）出现时拿走键盘焦点，除非焦点已在另一个 TSP 输入控件（`[data-tspi-keys]`）里。studio 输入框不算这种控件，所以正在输入框里打字时焦点也会移到门上。门被 omp 撤掉、焦点掉到 `<body>` 时，焦点回到 studio 输入框（`composer/use-reclaim-focus.ts`）。
- **键盘**：焦点在门里时，按键编码后写给 omp（`features/tsp/keys.ts` 的 `encodeKey`），选中、提交、取消都由 omp 决定；这些按键不会被输入框当成“停止任务”。omp 对提问的 `Esc` 是取消整个提问并结束这一轮。焦点在输入框里时 `Esc` 走 §5.2。
- **外观与按钮**：两种门都有外框（样式在 `interactive.css`），不加阴影，不像对话正文。`omp.btn` / `button` 节点画成 `ui/Button`（`interactive/Button.tsx` 负责 variant / tone / size 映射），点击发节点自己的 `actions.click`（没有就是 `click`），`disabled` / `busy` 时不发，不抢焦点；快捷键画成尾随的 `ui-hint` 小字，**键名按 Windows 写**（`fmt.ts` 的 `gateKeyHint`，不用 ⌃⌥⇧；`direction-3.2.md` §7 第 7 条；过程区的键帽不变）。提问的选项行前面画非交互的单选圈 / 勾选框（`shared/tsp/ask-gate.ts` 的 `askItemMarker`：单选题跟高亮走，多选题按 omp 节点的勾选状态），推荐值画成行内 `Badge`；多题页签是 `.ui-tabs`。审批卡是两列 grid，标题和只剩 Details 的底栏共用第一行（`interactive.css` 的 `[data-role="omp.editor.ask.approval"]`）。
- **超时**：由 omp 自己处理。提问的 `ask.timeout`（omp 默认关）打开时，倒计时画在提问对话框底栏，到期 omp 自动选第一项（`tsp-real-omp-probes.md` §6）。
- 录制和测试：`fixtures/tsp/{approval,ask,ask-multi}.jsonl`（omp 18.12，`row omp.btn`）、`button-approval.jsonl`、`button-ask.jsonl`（omp 18.18.6，`button` 节点）；单测 `test/tsp-gate.test.ts`、`test/tsp-ask-gate.test.ts`。细节见 `docs/architecture/tsp-migration.md` §7「button 和 shell 节点」、§10.6（提问对话框）、§10.7（审批与输入框）。
