# 4.19 SettingsPage

占据主区的页面（`direction-3.2.md` §4）。入口：侧栏底部 `设置`、`Ctrl ,`、命令面板 `设置`、斜杠 `/settings`；命令面板和斜杠命令可以直接定位到某一节（`showView("settings", { section })`：切到那一节、清掉搜索，焦点放到节标题；`/hotkeys` 和命令面板 `快捷键` 定位到通用页的快捷键分组并滚到眼前）。离开：`Esc`（搜索框里有内容时先清搜索）、导航顶上的 `返回任务`、`Alt ←` / 鼠标后退键，回到进入前选中的任务；进入前的焦点元素还在 DOM 里时焦点还给它。进设置不停止任何任务。

- **只有一列分节，不分"omp-studio 的 / omp 的"**：omp 的设置和终端共用一份，就是 omp-studio 的设置（仓库所有者定，2026-10-19）。
- 9 节固定、平铺、没有二级标题：`通用 / 模型角色 / Provider 与订阅 / 集成与插件 / 工具与权限 / Context 与记忆 / Subagent 与规划 / 高级 / 关于`（`SettingsNav.tsx` 的 `settingsPages`）。只有一两项或全是没翻译 omp 原文的节、和别处重复的节（用量、omp 版本）不单设（仓库所有者定，2026-10-22）。
  - `模型角色` 照 omp 的叫法 model roles（仓库所有者定，2026-10-24）；`Provider 与订阅`（仓库所有者定，2026-10-22）。
  - 集成和插件是一节，id `extensions`，不留旧节名的别名（仓库所有者定，2026-10-23）。
- `ui-store` 的 `SettingsSection` 是这 9 节 + `shortcuts`（通用页的快捷键分组），`SettingsPage` 是导航里的 9 节；当前节 `settingsPage` 和搜索词 `settingsQuery` 也在 `ui-store`，导航和内容共用。
- **各节只放常用项**（有人话标签的 omp 设置：`ompcfg` 字典里有 `<key>.label` 的键，`config-meta.ts` 的 `commonItems`，按字典顺序），和该节的管理列表同页；其余 omp 键全部进 `高级`。

**导航**（`SettingsNav.tsx`，`direction-3.2.md` §7 第 1 项）

- 进设置时侧栏列里渲染 `SettingsNav` 代替会话列表（`App.tsx`：`view === "settings"` 且不是窄窗），宽度就是侧栏宽度，照样可拖；退出时换回会话列表。自上而下：`返回任务`（右端淡色 `Esc` 提示，`settings-back`）、搜索框（`settings-search`，有内容时右端 × 清除）、9 个节按钮（`settings-nav-<节>`；当前节 `aria-current="page"`，搜索中没有当前节）、最底下版本行（`settings-nav-version`）。
- 版本行只写 omp-studio 的版本号，omp 的版本在“关于”里（仓库所有者定，2026-10-22）。
- 窄窗（侧栏变抽屉）或侧栏被收起时，导航改成内容顶上一行（`SettingsCompactNav`，`settings-nav-compact`）：节下拉（`settings-nav-select`）+ 搜索框。搜索中下拉没有选中项（选回当前节也能退出搜索），占位是当前节名——不用 `settings.search`，否则像有一节叫“搜索设置”。窄窗的抽屉里仍是会话列表。
- 设置页里 `Ctrl F` 聚焦搜索框（导航和内容共用 `onSettingsKeyDown`）。

**内容列与页头**（`SettingsView.tsx`、`settings.css`）

- 内容列**不设宽度上限、随窗口变宽**：窗口变宽右侧不能大片空白（仓库所有者定，2026-10-23）；设置页没有长段落正文，宽了也不难读。多出来的宽度由格子加列吃掉。
- **列数只按宽度定**，能放几列放几列（`.st-cells` / `.st-groups` 的 `auto-fill` + `--cell-min`；快捷键表同一种格子）（仓库所有者定，2026-11-09）。
- **一页一套列**（`features/settings/Cells.tsx`）：一页里连续的分组放在 `Groups` 里共用一套列，各组的格子是它的 subgrid，上下对齐；每格按"标签不折行 + 控件"的宽占一列或几列，按原来的顺序逐行往前填（`shared/ui/cell-packing.ts` 的 `packCells`：先填前面行的空位，行里不留空位）。
  - 坑：量宽时格子带 `data-measuring`，标签和控件排成一行、文本框和标签输入按固定宽算；不这样量出来偏窄，框会被挤到标签下面。e2e `omp-config.e2e.ts`「设置页格子」守着（高级页三种宽度下文本框都和标签并排）。
  - 只占一行、没填满的小组（`Group packable`）和相邻小组并排（如通用页「空闲任务」和「终端」）；带角色表的组总是整行。
  - 搜索结果按分组、用和各节页面一样的格子（`ConfigResults`）。没有分组标题、直接是格子的页（子代理）第一行上面补间距，各页内容起点一致。
- 节标题是页面的 `h1`；页头右边是动作槽（`PageHeadActions.tsx`，各节把 sm 控件 portal 进来）：Provider 与订阅 = `连接 provider…`（§4.20）；集成与插件 = `范围` 下拉（插件也用它，见下）。一页最多一个主按钮。
- 节内分组用 `ui/SectionHead`（标题 + 个数，右侧 ↻ 或 sm 按钮，可带一行说明）；管理块（MCP、SSH、自定义提供商、插件市场）的根节点带 `.st-section`，和上一块之间留分组间距。滚动条用 `ui/OverlayScrollbar`；换节或开始搜索时滚回顶部，换节时新节淡入（`motion.css`）。

**行**（`ui/Row`，样式 `ui/controls.css` 的 `.ui-row`；omp 设置的行是 `ConfigRow.tsx`）

- 一组行上边不画线（挨着分组标题，线太多），行之间一条淡分隔线、无底色；控件一律 sm。
- 标签是普通文字块；说明放标签后的 `ⓘ`（`ui/InfoTip.tsx`），不另起灰字。**标签折行时 ⓘ 和最后一个字一起换行**，不会单独掉到下一行。omp 设置的 ⓘ 里先写 key（等宽），再写说明；中文界面没有中文说明时直接显示 omp 的英文说明。没有人话标签的项，标签就是 key（等宽，长 key 折行，不截断）。
- 改过的值（和 omp 默认不同，`config-meta.ts` 的 `isModified`）：标签左侧一道强调色竖线，控件后一个"恢复默认"`IconButton`，悬停写默认值（`settings.cfg.default`）。
- 控件后面可能跟：`正在保存…`（`aria-live`）；warning 徽标 `被 {name} 覆盖`（生效值来自项目配置、叠加配置、运行时参数或环境变量，悬停写原因）。**保存成功弹 `已保存` toast**，不在行里占位——行内提示出现又消失会把旁边的控件挤来挤去（仓库所有者定，2026-10-23）；被覆盖时不弹（徽标一直在）。工具开关（`ToolsCard`）同样弹 toast。只有保存或校验出错时控件下才多一行红字；搜索命中的是说明而不是标签时，控件下就地显示那句说明。
- 凭据类（omp 标为 redacted 的项）不显示、不编辑，只有 `已设置` / `未设置` 徽标，ⓘ 里说明去终端用 `omp config` 设置。

**控件怎么选**（`ConfigControls.tsx`；只看类型和选项个数，不看语言和宽度，两种语言一致）

| omp 的类型 | 控件 | 何时保存 |
|---|---|---|
| boolean | `Switch` | 切换即存 |
| enum，≤4 个值 | `Segmented` | 选中即存 |
| enum，>4 个值 | `Select` | 选中即存 |
| number | `NumberField`（右对齐，单位写在框内，从 key 末段后缀推：`Ms`、`Seconds`、`Percent`；标签里不写单位）。omp 说明里写了特殊含义的值（如 `compaction.thresholdPercent` 的 -1，`config-meta.ts` 的 `numberSpecials`）在框里显示成占位文字，清空即存回这个值 | 停手、失焦或 Enter（`ConfigControls.tsx` 的 `textDelayMs`）；不是数字时不存，就地报错 |
| string | `TextField` | 同上 |
| 字符串数组（如 `task.disabledAgents`） | 标签输入（`TagInput.tsx`：Enter 或逗号添加，输入框空时 Backspace 删最后一个） | 每次增删即存 |
| `modelRoles`、`retry.fallbackChains` | `编辑…` + 等宽摘要（角色名 / 每条回退链的 key），对话框里是专门的编辑器（`StructuredEditors.tsx`：角色 → 模型下拉；回退链可增删、上下移，每项带思考强度下拉，换模型时档位新模型也支持才保留；候选和模型角色页同一份，`role-options.ts`）；值的结构认不出时退回下一行 | 编辑器里改动即存，`完成` 关闭 |
| 其余对象 / 数组 | `编辑…` + 等宽摘要，对话框里是等宽 `Textarea`；JSON 能解析、类型对且有改动时 `保存` 才可用 | 点 `保存` |
| `goal.continuationModes` | 开关「目标自动推进」（见本节末） | 切换即存 |

枚举的取值：有人话标签的常用项显示翻译后的取值；其余原样显示 omp 的取值，用等宽字。当前值不在可选项里（omp 版本变了、手改过配置）时保留为一项，不让控件悄悄显示成别的。omp-studio 自己的设置（通用页）用同一套 `Row` 和控件。

**高级**（`ConfigSection.tsx` 的 `AdvancedConfig`，`direction-3.2.md` §7 第 4 项）

- 页头下一行说明 `settings.advanced.note`（其余多少项 omp 设置，和终端版共用）。
- 左侧页内目录（随页面吸顶，`advanced-toc`）：omp-studio 的分组（`shared/ui/config-groups.ts`；没有项的组不出现）一行一个，带项数；当前分组展开它的前缀小组，点小组滚到它；换分组用 `ui/Reveal` 过渡。目录跟着滚动选中当前看得见的小组，滚到底时选最后一个。选中的分组和小组记在模块里，换节再回来保持原样。
- 右侧只显示当前分组的行，**全部平铺、没有折叠**：按 key 第一段分小组（`prefixGroups`，保持 omp 的顺序；只有一项的前缀和没有点号的键并进最后的 `其他`），小组标题是前缀的中文名（`prefix.*` 放悬停），右端只写 `M 项改过`（没改过的不写）。行里的 key 去掉小标题已经写出的前缀。
- 全部项（含文本框、标签输入、JSON）都进格子、保持 omp 顺序，列数按右栏自己的宽度算；英文 key 太长时控件换到 key 下面，key 只在点后面折行，不从单词中间断开。
- 常用项只在各节页面上，不在高级里重复；终端专用的键（`config-groups.ts` 的 `terminalOnly`）哪里都不显示。

**搜索**（`OmpConfigPane.tsx`，`config-meta.ts` 的 `matchesQuery`）

- 只搜 omp 的设置（常用项和高级，不含终端专用的键）：key、omp 原描述、中英两种语言的标签和说明，以及常用项所在分组的名字（搜 `subagent` 能找到子代理页的项），不区分大小写，多个词要全部命中。omp-studio 自己的设置不在搜索范围里。
- 有搜索词时内容换成结果：按 omp-studio 的分组各一个分组标题（带个数），行全部展开。没有结果时居中 `settings.search.empty` + `清除搜索`（`settings-search-reset`），给出下一步。命中的是说明时说明占满这一格的宽（不然开关的说明会被挤成一词一行）。点任何一节、清空搜索框（× 或框里 `Esc`）回到节内容。
- omp 没就绪时 omp 设置的位置显示 `settings.cfg.notReady`；读取中 `settings.cfg.loading`；读取失败是 error `Notice` + `重试`。

**格子排法**（各节通用；`.st-cells`）

- 列数随宽度、每格按内容占一到几列，每格一条 `ui/Row`，标签靠左、控件靠右，"恢复默认"夹在两者之间、出现时控件不动；内容区窄到只放得下一列时一格一行（仓库所有者定，2026-10-22）。
- **格子里标签和控件放得下一行就并排**，放不下才把控件换到标签下面、靠右（`.st-cells .ui-row` 是 `flex-wrap`）；明明放得下的不拆成两行（仓库所有者定，2026-10-23）。换到下面的文本框、标签输入占满整格；标签比整格还长时自己折行，不会被挤成一两个字一行。
- 各节的 omp 常用项按小块排（`config-meta.ts` 的 `commonBlocks`，按 key 前缀归块，每块一个小标题 `settings.block.<id>`；页面标题已经说明的块不写小标题），逐行填，所以字典里成对的项挨着放。开关、数字、分段 / 下拉、`编辑…` 进格子（`ConfigControls.tsx` 的 `fitsCell`；格子里 `编辑…` 后的摘要截断、悬停看全文，值为空时不写摘要——单独一个 `{}` 像图标不像值）；文本框和标签输入排在格子后面，一行一格（`.st-cells.st-wide`）。
- `记忆后端` 下拉也是一格，后端自己的设置按后端挨着排，标签带后端名，看得出归属。

**各节**

- **通用**（`GeneralSection.tsx`）
  - 分组 `外观`：先是**主题画廊**（`ThemeGallery.tsx`，`theme-gallery`，`role="group"`）：卡片顺序 = 跟随系统 + `themeNames`，每张卡一个按钮（`theme-card-<名字>` / `theme-card-system`，`aria-pressed` = 当前主题），点了就 `setTheme`。卡里上面是预览块，下面只有主题名，不加说明。预览块挂 `data-theme="<名字>"`，用那个主题自己的变量画迷你界面（侧栏条、主区插图、消息气泡、强调色圆点）；跟随系统的预览左浅右深。画廊下面是格子：背景图（`setting-backdrop`：主题插图 / 自选图片 / 不用；还没选过图时点自选图片先弹文件对话框，取消什么都不改；当前是自选图片时多一个 `更换图片…`，`setting-backdrop-choose`）、浓度（`setting-backdrop-strength`；背景图为不用时不出现）、毛玻璃（`setting-glass`；只在 `AppInfo.glassSupported` 时出现），出错弹 toast；然后是语言、字号（`setting-font-size`，按 pt 选、默认正文字号；整个软件等比缩放，实现见 §5.1）——用 pt 而不是缩放百分比（仓库所有者定，2026-10-23）；减少动效（系统已要求时禁用在"开"，后面徽标 `系统已要求`）、选中即复制（默认开，见 §4 通则）。
  - 别写不必要的二级标签和说明，让布局自己说明（仓库所有者定，2026-10-24）：悬停说明只留真正有信息的一句。
  - 分组 `通知与回顾`（`settings.notifications`，`notify-settings`）：omp 的三项通知（`ask.notify`、`completion.notify`、`error.notify`，各是开启 / 关闭分段，和终端共用）+ 空闲回顾（`recap.enabled`、`recap.idleSeconds`）+ studio 自己的完成提示音（`settings.soundOnDone`，默认关：正常跑完一轮响一声 `shell.beep()`，窗口可见也响；出错、中止不响；窗口在托盘、已发完成通知时不另响，`gate-notifier.ts`）。**系统通知只看 omp 的这三项**，studio 没有自己的通知开关（见 `docs/architecture/omp-settings.md`「studio 的系统通知遵守 omp 的 `*.notify`」）。
  - 分组 `任务运行中`（`settings.whileRunning`）：Enter（`settings.enterBehavior`，插话 / 稍后，studio 自己的设置）+ omp"对话行为"组的其余常用项。
  - 分组 `空闲任务`（`settings.idleTasks`）：`空闲后关闭进程`（`setting-idle-close`，选项和默认值见代码）。
  - 分组 `终端`（`settings.terminal`，issue #9）：`Shell`（`setting-terminal-shell`：自动 / 本机检测到的 shell / 文件对话框选过的那个）+ `选择文件…`（`setting-terminal-shell-choose`）；只影响之后新开的内置终端，机制见 `docs/architecture/terminal.md`「Shell 和环境变量」。
  - 分组 `快捷键`（`id="settings-shortcuts"`）：只读，和上面的格子同一套列；键名是淡色等宽字，不画键帽（几十个键帽太吵）；动作名放不下时折行、不省略。v1 不可自定义。下面一组 `omp 快捷键`（`settings.shortcuts.omp`，`omp-shortcuts`；标题下不写说明，仓库所有者定，2026-10-23）：列出当前转发给 omp 的动作和键（`shortcut.omp*`），键位来自 omp 的默认键位加 `<agent 目录>/keybindings.yml`，只读，要改去终端或那个文件里改（§5.1）。
- **模型角色**（`ModelsSection.tsx`，`.st-roles`）：两组角色表，角色名照 omp 18.12.6 的 `MODEL_ROLES`（`config/model-roles.ts`），悬停 ⓘ 是每个角色一句用途（`model.role.hint.<角色>`，自定义角色没有）。
  - **对话模型**（`settings.block.defaults`）：上面先是一格普通设置 `默认思考强度`（`setting-default-thinking`，在 `.st-cells` 里；不放进角色表，否则长标签把角色名列撑宽、下拉对不齐），角色表是 omp 的对话角色 + `modelRoles` 里另有的自定义角色。**特定能力的模型**（`settings.block.kinds`）：Image / Web / Speech / Dictation / Judge。
  - 自定义角色（仓库所有者要求，2026-10-24）：那一格主模型行末尾有 ×（`setting-role-<角色>-remove`），删掉 `modelRoles` 里这一项和它的 `retry.fallbackChains`，不确认；表下面 `+ 添加角色…`（`setting-role-add`）开「添加自定义角色」对话框：名字（`composer/model-groups.ts` 的 `customRoleNamePattern`，和已有角色重名——不分大小写——时报错）+ 模型，两个都填了才能添加——omp 只认有模型的角色，所以名字和模型一起写进 `modelRoles`。
  - 一行两个角色格，按阅读顺序填（仓库所有者定，2026-10-23）；内容区窄时一行一格（再窄模型名会被截断）。
  - **每格四列，同一列共用列宽**（subgrid）：角色名（定宽，两张表、左右两半的下拉左边线对齐）| 模型 | 思考强度 | 删除。第一行是主模型（`setting-role-<角色>`，Default 的是 `setting-default-model`）+ 角色自己的思考强度（`setting-role-<角色>-thinking`）。
  - **每个备用模型各占一行**（仓库所有者定，2026-10-23），按 `retry.fallbackChains.<角色>` 的顺序，和主模型同列同宽：可换的模型 `Select`（`setting-chain-<角色>-<序号>`）| 思考强度（`ChainLevel.tsx`，`setting-chain-<角色>-thinking-<序号>`）| ×（`setting-chain-<角色>-remove-<序号>`）。最后一行是 `添加备用…`（`setting-chain-<角色>-add`），平时只有次要色文字、悬停或键盘到时才出框（一屏十几个虚线框太吵）。左右两格高度不同时内容靠上。

  - `已安装`（右侧有市场插件时 `升级全部`，再一个 ↻）：元信息 `版本 · 说明`；动作 `详情`（`Disclosure`）+ `升级`（只有市场插件）+ 启用开关 + `卸载`（先确认）。展开后 npm / link 插件有 `功能`（每项一个开关，默认开的标 `默认`）和 `设置`（布尔 = 开关、枚举 = 下拉、其余 = 输入框 + `保存`；已设置的算改过，有恢复默认；值不能以 `-` 开头，omp 会当成选项）。市场插件没有 `详情`；`功能`、`设置` 哪个为空就不画那个小标题，两个都空则没有 `详情`。

  - **预设市场**（仓库所有者要求——“插件不知道咋装”，2026-10-24）：列表下面一组 `ListRow`（`marketplace-presets`；标签 + 来源 + `添加`，`marketplace-preset-<市场名>` / `marketplace-preset-add-<市场名>`），常量 `PRESET_MARKETPLACES`（`omp-output/plugins.ts`），来源见 https://code.claude.com/docs/en/plugins/anthropic-marketplaces 。omp 回报的市场名或来源等于预设的就不再显示；没有任何市场时这就是插件区的入口，不另写空状态。点 `添加` 走 `marketplaceAdd`，成功后自动展开该市场的 `浏览`。只放在列表里，添加对话框留给自定义来源。
