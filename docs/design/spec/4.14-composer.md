# 4.14 Composer

**尺寸与结构**
- 外容器宽 = 列宽，输入区和工具行在同一块底上、**中间不画分隔线**（样式 `composer.css`、`--radius-composer` 等 token）。悬停和聚焦都只把边框加深成 `--border-strong`，不画紫边和外圈：输入框几乎一直聚焦着，紫色会一直在（不走通则的 `--accent` 焦点环）。
- 文本区：最小 1 行（空状态与对话中同高），自动增高到上限后内部滚动，`resize: none`。**高度可拖**：顶边拖拽条（`composer-resize`，`role="separator"`）向上拖变高，上限是主区高度的一个比例（`field-height.ts`，窗口变矮时重新夹取）；拖到的高度是下限，内容多了照样自动增高；键盘 ↑↓ 微调，双击还原成自动增高；整个应用一个值（`field-height-store.ts`）。**点外框里的空白**（工具行空处、文字区四周留白）：焦点留在 / 回到文本框，光标位置不变（`ComposerInput.tsx` 的 `keepFieldFocus`，草稿和任务都挂在 `.composer` 上），否则焦点掉到 `<body>`，打不了字。
- 底部工具行：左起 ModelChip、ApprovalChip、文件夹标签（草稿 `empty-project`、任务 `composer-folder`，§4.7；只读）、会话开关胶囊（只有任务有，见下“会话开关菜单与模型预设”）；工具行上的胶囊（以及输入框上方的待办板按钮）统一是 `.ui-chip`（§4.23）。
  - 没有附件按钮，附件只来自粘贴和拖入（2026-10-22 仓库所有者定）；模型和审批胶囊后面不带 `⌄`（2026-10-21 仓库所有者定）。审批胶囊写图标 + 模式名（`direction-3.2.md` §7 第 10 条），见 §5.8，“全自动”用警示色。
  - 右起上下文圆环（`ContextMeter`，见下）、本会话费用（`SessionCost`）、提示词优化（`EnhanceButton`，见下）、SendStop。**右端就是上下文、费用、优化、发送这四个**（2026-10-23 仓库所有者定前三个；2026-11-09 仓库所有者批准把优化放在发送键左边：离发送最近，改写完顺手就发）。
  - 费用：对应 omp 状态栏的 cost 段（`get_session_stats.cost`，按 API 价格估算，订阅登录的模型也照样累计）；不到一美分保留 4 位小数；一直显示，草稿和还没有统计时是 `$0.00`。有子代理花费时后面跟 ` (0.42)`（`usage-subagents`；omp 费用段的第一个数不含子代理；omp 写 `(+0.42)`，仓库所有者 2026-10-25 定去掉 `+`）。当前模型的 provider 有 OAuth 凭据时（omp 优先用 OAuth，`get_logout_accounts`，按 provider 缓存）后面跟 ` (sub)`，悬停换成 `composer.usage.costTipSub`。是按钮，点开 `UsageDialog`。
  - 空间不够时的让位顺序：项目路径先缩到只剩文件夹图标，再隐藏思考强度后缀（完整的在胶囊悬停里），模型名最后才省略且不窄过 `--chip-name-min-w`（开着子代理 / 文件面板时不至于缩成 “D…”）；审批胶囊和仪表不收缩；更窄时（比如开着文件预览）工具行折成两行：模型、审批在上，其余换到下一行靠右；圆环和费用一直在。断点在 `composer.css`。本会话 token 不在工具行里，在上下文浮层的“会话用量”里。
- **提示词优化**（2026-11-09，仓库所有者批准；`EnhanceButton.tsx`、`use-prompt-enhance.ts`，调用 omp 和实测见 `docs/architecture/prompt-enhance.md`）：发送键左边一个 `IconButton`（四角星，`enhance-button`，`composer.enhance`），草稿页和任务都有，任务运行中也能用。草稿去掉附件占位符后为空、或以 `/` 开头时禁用。点一下：主进程用 `omp -p --no-session` 把**草稿文字**（附件和大段粘贴只以占位符出现；不带对话、工具、AGENTS.md）交给 omp 的 smol 角色改写（smol、default 都没配时用当前任务的模型，草稿页用新任务默认模型）；进行中 ✦ 形变成 ×（§2.6），再点或 `Esc`（§5.2）= 停止。结果**一次替换**草稿（`execCommand("insertText")`，`Ctrl Z` 一步回到原文），不自动发送、不弹预览；草稿一变（编辑、发送、换任务）就立刻取消、丢掉结果。失败不碰草稿：没有模型 toast `composer.enhance.noModel` + 打开模型选择器角色范围的动作；结果丢了附件占位符 `composer.enhance.markersLost`；其余 `composer.enhance.failed`，omp 原话在悬停里。没有命令面板项和快捷键（键位没定）。

**后台任务**（仓库所有者定：直接打开 omp 的 `/jobs` 弹窗，studio 不做自己的看板——转述的看板查看输出、结束都还要再点进 omp 的弹窗）：药丸 `⚡ N`（`pill-jobs`）点击 = `openTspJobs(taskId, 第一个运行中的作业)`（`tsp-jobs-store.ts`）——hud 有作业胶囊就对它发 `action jobs.open`，没有就 `sendPrompt("/jobs")`；弹窗（`omp.overlay.jobs`，TspView 照常渲染）出现后对这个作业的列表项发 `select`，已开着就只发 `select`。超时内弹窗里没有这个作业（omp 已经不列了）就停在弹窗上。
- **作业数据**（`src/shared/tsp/jobs.ts` 的 `deriveTspJobs` / `mergeTspJobs`）：从 omp 的节点推出，`tsp-jobs-store.ts` 只在作业相关节点（`JOBS_NODES`）变了的批次后合并，纯文字流式批次不扫描。药丸数 = 除子代理外所有运行中的作业（bash、eval、后台 task，`runningJobs`）。`/jobs` 由 studio 接管（`jobs-slash.ts`）：不带参数和点药丸一样，选中第一个运行中的作业，没有就选最近的那个；这个任务没有作业时提示、不打开；`/jobs kill <id>|all` 直接结束（`runTaskCommand {kind:"jobsKill"}`；omp 成功时没有回应，出错才弹 toast）。已结束的作业只有 omp 的 `/jobs` 弹窗开着时才在文档里，store 按“运行中消失 = 完成”和结束动作自己记录，不保证重启 studio 后还在。omp 自己的 hud 作业胶囊（`omp.hud.seg`）不画。
- **输入框上方**（2026-10-21，仓库所有者定，照 Tern；`features/composer/ComposerTop.tsx`，`composer-top`）：输入框正上方、列宽，自上而下最多两行，`Reveal` 展开收起：
  - **药丸行**：右对齐一组分段样子的 `[👥 N | ⚡ N]`（`StatusPills.tsx`，`status-pills`；`--bg-active` 槽，子代理面板开着时左半段是 `--control-on` 块，同 §4.23 Segmented），两个半段是各自独立的按钮；同一行的扩展状态标签、取消 / 重试按钮和它同一档高度（2026-10-29）。**左半段** = 运行中的子代理数（`pill-agents`；`agent-hub.ts` 的 `countActiveAgents`，按名字去重），点击 = 开关右栏子代理面板（`toggleAgentsPanel`，§4.28）；**右半段** = 运行中作业数（`pill-jobs`），点击见上“后台任务”。**每段只在个数 > 0 时画**，都没有就不画药丸（弹窗仍可由 `/jobs` 打开）。左半段悬停 / `aria-label` 是 `composer.pills.agents`；右半段悬停或键盘聚焦出**作业卡片**（`jobs-card`，2026-10-23 仓库所有者定，代替悬停提示）：`.ui-popover` 外观、不接指针，不超出窗口顶（作业多、窗口矮时截掉）；挂在 body 上、`--z-tooltip`（输入框的层叠上下文低于过程区的 layer，留在里面会被开着的 omp 弹窗盖住）；每个运行中的作业一块：命令 + id + 类型小标签（`jobs-card-type`：bash / eval / task，omp 的叫法不翻译），omp 给了进度时一行进度条（复用 TSP 的 `MeterView`）。内容是 omp hud 作业胶囊的悬停卡片（`jobs.ts` 的 `deriveJobTiles`），omp 还没给时只有标题。**位置**：有待办板时药丸单独一行、在状态行正上方；没有时并到状态行右端（运行中）或直接在输入框上面（空闲），不留空行。
  - **Shell / Python 标签**（`ShellTag.tsx`，`shell-tag`）：输入框文字以 `!` / `!!` / `$` / `$$` 开头时出现在会话开关右边的 `ui-chip`（`Shell` / `Python`）；点开一行“结果进入 context”开关（`shell-in-context`），开 = 单前缀、关 = 双前缀，切换改输入框文字的前缀；前缀没了标签和浮层一起消失。工具行胶囊（模式、会话开关、Shell）的浮层都和胶囊右缘对齐往左展开（`align="end"`），不伸出输入框右缘。
  - **状态行**（`.run-status`，§4.11）：左 = 运行图标 + 翻牌计时 `FlipText` + 当前活动；右 = `TodoBoard`（§4.6）。运行图标是标志里的像素 π（`PiWriteMark`，2026-10-24 仓库所有者定），按笔画顺序亮起再褪成淡影，纯 CSS；减少动效时停成完整的 π；等你确认时换成静止的琥珀色点。只在任务启动中 / 运行中 / 等你确认或有待办时出现。
  - omp 自己的 HUD（`omp.hud` 的作业 / 子代理胶囊、`omp.hud.activity` 的运行状态行和待办药丸，`HIDDEN_HUD_ROLES`）不画，数据都在 ComposerTop 里；omp 的 Stop 键帽也不画，停止用发送 / 停止键和 `Esc`。
  - **模式胶囊与状态区的 omp 信息**（omp 18.12.6 实测，见 `docs/architecture/conversation.md`「模式与状态区」；`ModeChip.tsx`、`ComposerNotes.tsx`、`session-toggles/ModeSection.tsx`）：①工具行会话开关右边的**模式胶囊**（`mode-chip`，`data-mode` / `data-paused`）只在 omp 状态行有模式（Plan / Plan (paused) / Prewalk / Vibe / Loop）时出现，暂停用警示色；点开是当前模式的控件（Plan 开关 + 重新打开计划评审；Plan 暂停 = 关闭；Vibe 开关；Prewalk 停用；Loop 状态 + 暂停（运行中）+ 停止）。没有模式时同一组开关（Plan、Vibe、Loop 表单）放在会话开关菜单底部，说明放悬停；目标模式开着时都禁用并说明。界面只显示 `TaskState.composerMode`（omp 状态行回读），命令没生效就弹 omp 原文错误。②状态行：自动重试 = 倒计时圆环 + “第 N/M 次重试 · Ns” + 取消（omp 的 `interrupt`）；压缩 = 不定进度条 + 取消；能取消的空闲 loader 带取消；空闲时 omp 的 `omp.hint.retry` = “上一轮被中断” + 重试（`/retry`）；右侧只读小标签 = 扩展 `setStatus`。③**聚焦横幅**（`run-focus`）：omp 聚焦到子代理时写“正在给 X 发消息” + “回到主会话”，占位符同步换成“给 X 发消息”。
  - **小窗口**：输入框和它上面这块是 `flex: none` 的整体，**永远完整可见**；让出高度的是对话滚动区（`.tsp-view`、`.tsp-scroller` 都要 `min-height: 0`），e2e 在几种窗口尺寸断言工具行在窗口内、药丸不压输入框、对话区留有高度（`test/e2e/tsp.e2e.ts`）。旁路提问和终端同时开着、加起来比主区高时，旁路提问（可缩到 0）和终端（有最低高度）也让出高度，输入框和终端的提示行都留在主区里（e2e `terminal.e2e.ts`「窗口很矮时旁路提问、输入框、终端一起放得下」）。
- **过程里的作业磁贴**（`omp.job.tile`，Task / wait 工具卡的 body，`tsp.css`）：没有自己的底色和外框（层级靠底色，不靠一圈圈的线），只用细线和卡片头、相邻磁贴分开。
- 草稿的工具行在审批胶囊右边多出项目标签（§4.7；worktree 选项在顶栏的分支胶囊里，§3.1）。发出第一句话换成任务输入框时：文件夹标签留在原位，焦点在绘制前就落到新输入框（App 的 layout effect），边框不做过渡（`data-from-draft`），所以看不出换了一个输入框。
- 工具行各项**从第一帧起都在原位**：模型、审批胶囊、圆环、费用直接画出来，数据到了再填，不等 omp。数据先用上次读到的（主进程每次现读成功就记进 `userData/startup-cache.json`；渲染进程首帧前取 `getStartupSnapshot()`），现读到了再替换；从没读到过（第一次启动）时模型胶囊写 `composer.modelLoading`、审批胶囊是图标 + 骨架条（`aria-busy`，不写假的省略文字），圆环是不能点的空环（`data-pending`）。任务进程起来之前胶囊用上次的模型目录里的名字和窗口（不是模型 id）。主进程在应用启动时就拉起服务进程读默认模型和模型目录，不等输入框来要。
- **切项目时模型胶囊第一帧就是最终值**：不经过“上一个项目的模型 / `composer.modelLoading` / `composer.noModel`”这类中间状态。渲染进程按项目记最近一次现读的新任务默认值（`composer/new-task-default.ts`，没读过的项目退回启动缓存），草稿胶囊每次都按**当前项目**的记录算，读不到就保持，绝不显示别的项目的值；任务进程起来之前（`stopped` / `starting` 且还没有模型）用同一份记录和算法先画，主进程随后报出的是同源的值。**思考强度**：取项目 `omp config list` 的 `defaultThinkingLevel`（没有就用 omp 自选默认模型的档位）；模型认出来后按它的档位钳制，不支持思考不显示；模型认不出（目录没到，或 `modelRoles.default` 指向目录里没有的模型）时原样显示配置的档位。
- **冷读占位与单一算法**（逐帧复现定下的）：切到一个本次运行和启动缓存都没读过的项目时，项目默认值或模型目录有一样没读到，胶囊就是占位 `composer.modelLoading`、**不带强度**，两样都到了一次换成最终值（`shared/ui/new-task-default.ts` 的 `pending`）——拿全局默认值先顶上会在同一个项目里连变好几次（`test/e2e/model-chip.e2e.ts`）。读不到项目配置（omp 没就绪）时按“什么都没配”算，不一直占位。`modelRoles.default` 指向目录里没有的模型时胶囊写它的名字，不写 omp 自选的那个。草稿、起进程前的任务输入框、主进程 TSP 任务状态（`tsp-runner.ts`）共用这一份算法，都要钳制档位，否则配的档位不在模型支持范围内时胶囊只剩模型名。顶栏分支按钮（`GitTools`）的状态连同任务 id 一起记，切到非 git 任务第一帧就不画（`test/e2e/git-worktree.e2e.ts`）。
- **附件卡片与 `#N` 芯片**（`ComposerInput.tsx`、`Attachments.tsx`，机制和 omp 实测见 `docs/architecture/composer-attachments.md`）：附件卡片在输入框**顶部**，每张 `attachment`：缩略图 + `#N` + 像素尺寸，右上 ✕（`attachment-remove`，悬停 / 聚焦才显示）。来源是粘贴和拖入的图片。**非图片文件**（拖入、粘贴）同样是卡片 + `[File #N, 名字]` 芯片，发送时换成 omp 的 `@"路径"` 提及；路径只在 preload / 主进程里，渲染进程只有不透明 id（同文档 §2.1）。当前模型不收图片时 toast `composer.attach.unsupported`。文字里引用附件的是 omp 的占位符 `[Image #N, WxH]`，显示成 `#N` 芯片（`.composer-chip`）；芯片是原子的（光标不能落进去，Backspace / Delete / ← / → 一步越过，删芯片 = 删附件，删卡片 = 删芯片）。**大段粘贴**（超过 omp 的阈值）折叠成 `[Paste #N, +X lines]`，显示成 `#N +X 行` / `#N M 字符` 芯片，发送时换回原文；`Ctrl+Shift+V` 原样粘贴不折叠（omp 的 `pasteTextRaw`）。大段粘贴在顶部也有卡片（issue #9）：`#N` + 行数 / 字数 + 第一行非空文字；点卡片开只读预览（`paste-preview`），底下“展开成文字”（`paste-inline`）把占位符换回原文。发送时图片按文字里引用的编号重排、没引用的不发。
- **粘贴文件夹**（照终端）：资源管理器里复制的文件夹粘贴进输入框时插入绝对路径（含空白的加双引号，多个用空格隔开）。路径由 preload 在隔离世界里用 `webUtils.getPathForFile` 取，`execCommand("insertText")` 插入（`Ctrl Z` 能撤回），渲染进程拿不到路径（`src/preload/index.ts`，同拖入文件夹）。
- 草稿按任务保留，由主进程持久化。
- 占位符：新任务 `composer.placeholderNew`；有对话 `composer.placeholder`；运行中 `composer.placeholderRunning`（不写键位，键位在停止键悬停 `composer.sendKeys` / `…Swapped`）；有门 `composer.placeholderGate`；worktree 被删 `error.worktreeMissing`（输入框禁用）；会话文件被删 `error.sessionMissing`（输入框可用，发出去就是新会话，§7）。
- **输入法**：`isComposing` 或 `keyCode === 229` 时 `Enter` 一律不发送；组合结束后才发送。（测试必写。）

**输入框与过程区的分工**：输入框上方的整个过程区——对话、工具卡片、待办、子代理、后台任务、HUD、omp 的排队（`omp.queue`）、提问 / 审批（`omp.editor.ask`、`omp.editor.ask.approval`）、选择器等浮层——是 omp 发来的 TSP 节点（`features/tsp/TspView`，见 `docs/architecture/tsp-migration.md`）；输入框和它下面的一切是 studio 的 `Composer`。所有任务都是 TSP，所以同一段对话在 studio 和 Tern 里显示一样。
- 布局：`TspView` 在上（内部滚动，吸底），`Composer` 在下；TSP 的 dock（HUD、排队、提问 / 审批）紧跟在对话后面、宽同对话列。**门跟着对话走**（2026-10-29，仓库所有者定）：对话比视口短时 dock 就在最后一项下面隔普通块间距，空白在 dock 下面；对话长过视口时 dock 停在过程区底部、Composer 正上方。做法是 inline 对话区的滚动区 `flex: 0 1 auto`（`tsp.css`）。omp 自己的输入框卡片（dock 里 role `omp.editor`）**不渲染**（`TspChildren.tsx`），所以也没有看不见的编辑器抢键盘焦点；对话列宽（`resizeTsp` 的列数）照旧量对话列。提问 / 审批被撤掉、拿着焦点的选项列表消失后，焦点回到 studio 输入框（`use-reclaim-focus.ts`）。过程区里的 `Esc` 是写给 omp 的按键，不触发 Composer 的“停止”。

**发送行为**

| 状态 | `Enter` | `Ctrl+Enter` | `Shift+Enter` | 按钮 |
|---|---|---|---|---|
| 空闲 | 发送（`prompt`） | 发送 | 换行 | 发送 ↑ |
| 运行中 | **插话**（`prompt` + `streamingBehavior: "steer"` 或 `steer`） | **稍后**（`follow_up`） | 换行 | 停止 ■ |
| 等你确认：审批（§4.17） | 有草稿：**拒绝并发送**；空草稿：不动作 | **批准**（有没有草稿都一样） | 换行 | 同运行中 |
| 等你确认：提问（§4.17） | 不发送 | 不发送 | 换行 | 发送键禁用 |

运行中发消息必须指明行为：wire 里 `prompt` 的 `streamingBehavior?: "steer" | "followUp"` ✔ 存在，`rpc.md` 说流式中缺省会失败（以 `rpc.md` 为准）。设置页可对调 `Enter` 与 `Ctrl+Enter` 在运行中的含义。

- 每日用量：全年热力图（`HeatmapView`）**占满对话框内容宽度**：格子边长由 `ResizeObserver` 按容器宽度和周数算出（`--uq-cell`，有上限），星期、月份标签跟着对齐（最后两列的月份标签靠右写，不被裁掉），不出横向滚动条；只按花费着色，悬停给日期、金额和请求数。

**速度开关与指示**（`get_state.fastModeEnabled/fastModeActive/slowModeSupported/slowModeEnabled/slowModeScope`；命令 `set_fast_mode` / `set_slow_mode`）：ModelPicker 底部控件行、思考强度右边，只在高亮行是**正在生效的模型**时出现（草稿里不出现）。两个开关排一行，每个是标签 + `ui/Segmented` sm 两段（`model.off` / `model.on`）。`快速模式`始终可点（RPC 没有“是否支持”字段；不支持的模型 omp 返回 `Fast mode is unavailable for the current model.`，原文进 toast）。`慢速模式`只在 `slowModeSupported` 时出现，范围是 `global` 时悬停 `model.slow.scope.global`。
- ModelChip：`fastModeActive` 为真时一个实心闪电（`chip-fast`）挂在刻度左上角当角标，刻度颜色照旧表示强度；没有刻度时闪电跟在模型名后面；悬停写 `{模型} · 快速`。慢速开着时一个 `慢速` 小胶囊；都关时不显示。omp 出错换成了备用模型（`TaskState.fallbackModel`）时模型名后一个警告色小胶囊 `备用`（`model-fallback-badge`，悬停 `composer.badge.fallbackTip` 写出换成的模型；子代理详情头行同款 `agents-fallback-badge`）；omp 的警告行 `row role=omp.notice.warning`（如 `Fallback: a -> b`）画成警告色底条。
- 实测（Tern omp，临时 agent 目录）：fast 只对本会话有效，**不落配置**，切到不支持的模型会自动关；slow 在 Anthropic 模型上 scope 是 `global`，**落在 omp 配置里**并跨进程保留（`session` 范围对应 OpenAI/Google 的 flex 层级，未能实测）。studio 不存副本；键入的 `/fast`、`/slow` 照常走 omp，本地完成的斜杠命令（prompt 应答 `agentInvoked:false`）之后主进程会重读 `get_state`。

**SlashMenu**：行首 `/` 打开，浮在输入框上方，最多同时显示 8 行，更多的在菜单内滚动（选中行始终可见）；上方放不下（窗口矮）时缩到主区顶边为止（`ui/Popover.tsx` 的 `useFitInside`，`@` 文件菜单和 Ctrl+R 浮层同）。`[/名称][描述]`，`↑↓` 选，`Tab/Enter` 补全，`Esc` 关闭；匹配见 `slash-match.ts`。数据 = 命令表（见下“斜杠命令表和守卫”）；studio 接管的命令（`studio-slash-table.ts`，描述 `slash.*Desc`）发送后开 studio 自己的界面而不是 omp 的终端弹窗，TSP 任务和新任务草稿页各取其中能用的子集。任务输入框和草稿页都有这个菜单。无匹配 `slash.empty`。

**斜杠命令表和守卫**（`slash-guard.ts`）：命令表 = 任务目录里项目 rpc-ui 的 `get_available_commands`（含项目 skill、自定义命令、扩展命令；敲 `/` 时重取一次，omp 推 `available_commands_update` 时整份替换）+ TUI 才有的命令（`shared/omp-tui-commands.ts`，omp 18.12.6）+ studio 接管的命令（`/goal`、`/tree`、`/fork` 等，发送时由 studio 处理、不发给 omp）。草稿以 `/名称` 开头、命令表已载入（非空）、`名称`（含别名）不在表里时，第一次发送不发出（omp 会把它当普通文字发给模型），输入框上方出现提示 `slash.unknown`（`.suggest` 样式）+ `slash.sendAnyway` 按钮；对同一段文字再发一次或点按钮才作为普通文字发出，改动文字提示即消失。命令表未载入时不拦；`/usr/bin` 这类带第二个 `/` 的不算命令。会结束或重启 omp 进程的 `/exit` `/quit` `/q` `/restart` 不在菜单里，手敲照常发出。接管的命令按参数分派：`/model 词`（唯一匹配直接切换，多个打开选择器并填好搜索词，`@角色` 进角色范围）、`/effort 档位`、`/todo start|done|drop|rm|append …`、`/settings 关键词`；不认识的参数原样交给 omp。

**BtwPanel**（旁路提问，`/btw [问题]` 或命令面板“旁路提问（/btw）”打开，`features/btw/`；语义和实测见 `docs/architecture/conversation.md`「旁路提问」）：停在输入框正上方、宽 = 列宽的卡片（边框同提问 / 审批门），高度不超过对话区的一个比例，内部滚动。

**输入历史**（`input-history.ts`、`history-store.ts`）：输入框为空（或光标在最开头）时 `↑` 翻看发过的消息（最近的在前），`↓` 往回走，翻过最新一条恢复翻看前的草稿；翻看中 `↑` 要光标在第一行、`↓` 要光标在最后一行才接管。斜杠菜单 / `@` 菜单打开时 `↑↓` 归菜单；刚翻出来的文本不开菜单，免得抢走后面的 `↑↓`。条目 = 会话里的用户消息（omp 文档里的 `omp.user`，含恢复的旧会话；`shared/tsp/user-messages.ts`）+ studio 自己按项目持久化的历史（`userData/input-history.json`，条数和单条长度有上限，只存文字，含斜杠命令、排队中、草稿页发出的第一句；主进程 `input-history-store.ts`；不读 omp 的 history.db），按发送顺序合并、相邻重复只留一条（`mergeEntries`）。新任务草稿也能翻项目历史。
- **Ctrl+R 浮层**（`HistorySearch.tsx`，`history-search`，外观同斜杠菜单）：顶上搜索框 `history-query`，下面匹配行 `history-row`（最新的在前，多行消息只显示第一行加 ↵）。输入框里按 `Ctrl R` 打开；多个词都要出现（不分大小写）；`↑↓` 选，`Enter` 或点一行把整条消息填进输入框（替换草稿文字）并关闭，`Esc` 或点浮层外关闭，Esc 不触发“停止任务”。焦点在过程区时 `Ctrl R` 仍转发给 omp（它自己的 History 选择器）；omp 把选中的历史写进它隐藏的输入框时，studio 把那段文字挪进自己的输入框（`docs/architecture/composer-input.md`）。

**FileMenu**（`@` 文件引用，`file-complete.ts`、`use-file-menu.ts`、`FileMenu.tsx`）：光标前的词以 `@` 开头（文本开头或空白之后）时，在输入框上方打开和斜杠菜单同款的菜单，靠左、不铺满输入框（铺满时一行里大半是空白），每行一个相对路径（目录部分 `--text-3`），`↑↓` 选，`Tab/Enter` 把 `@词` 换成 `@相对路径 `，`Esc` 关闭（到这个 `@词` 变化为止），空查询列出浅层文件。数据 `listProjectFiles({ kind: "task", taskId } | { kind: "project", projectId }, query)`（`src/main/files/project-files.ts`）：主进程按任务（草稿按项目目录）查出 cwd，优先 `git ls-files -co --exclude-standard`，不是仓库时退回有界遍历（跳过 `node_modules`、`.git`、符号链接）；有缓存和条数上限，按前缀 > 文件名前缀 > 文件名包含 > 路径包含 > 子序列排序，只返回相对路径，含空白的路径不收；`query` 含绝对路径或 `..` 时 reject。引用由 omp 展开成 `fileMention` 消息，studio 只做补全。

**会话树与分叉**（`SessionTreePanel`，`App.tsx` 在 `TspView` 旁挂它；数据与动作见 `docs/architecture/session-tree.md`，实测 omp 18.12.5）：`ui/Dialog` md（`session-tree`，标题 `tree.title` + ×，Esc / 点遮罩关闭并还焦点，打开时焦点在节点列表上）。
- ①节点只读 omp 会话文件（不拉起进程），叶子 = 文件最后一个条目；当前叶子所在行有 `Badge` `tree.current`。②选中 = 驱动 omp 自己的 `/tree`（同一个会话文件里移动叶子，不新建文件，原来的分支留在文件里，omp 重画对话），文字追加进输入框。③每行悬停 / 选中时出现“从这里分叉”（`session-tree-fork`，`Shift+Enter` 同效）：新任务由 `omp --fork=<原会话文件>` 起、再在新进程里回溯，期间标题换成 `tree.forking`，成功后关对话框并选中新任务。页脚左侧勾选框 `tree.summarize`（`session-tree-summarize`，有节点时才有）：勾上后选中 = 让 omp 先给被放弃的分支写摘要再回溯，期间标题 `tree.summarizing`，对话框保持打开。④omp 在用户消息卡片上画的“回退”图标（`actions.click: "rewind"`）由 studio 接管：打开这个对话框并把光标放在对应的那条消息上（按卡片从末尾数第几张对位），不把 `rewind` 发给 omp。⑤`/tree`、`/fork`、命令面板“会话树”都能用；`/fork` = 从当前分支最后一条用户消息分叉。
- **标签、压缩点、分支摘要、搜索和回溯提示**（实测 omp 18.12.6，细节见 `docs/architecture/session-tree.md`「标签、压缩点、分支摘要、搜索」）：①除用户消息外还有 `compaction`（压缩点，`tree.compaction` + `tree.compactionTokens`）和 `branch_summary`（回溯时 omp 给被放弃分支写的摘要，`Badge` `tree.branchSummary` + 摘要第一句）节点（`SessionTreeNode.kind`）；它们不能回溯 / 分叉（点击无事发生，没有分叉按钮）。②omp `/tree` 的标签（`label` 条目）显示成 warning 色 `Badge`（`session-tree-label`）排在文字前；每行悬停 / 选中时多一个“添加 / 修改标签”（`session-tree-label-edit`，`Shift+L` 同效；任务不空闲时置灰，悬停 `tree.labelBusy`），点后这一行就地变成输入框（`session-tree-label-input`，Enter 保存、Esc 取消，留空 = 清除），保存由主进程驱动 omp 的 `/tree`（`select` → `action label` → `edit` → `action label-save` → Esc，`labelTreeEntry` IPC），成功后重读树；编辑标签的行不挂悬停提示。③列表上方搜索框（`session-tree-search`，占位 `tree.searchPlaceholder`）：按消息文字和标签过滤（空白分词、全部词都要出现、不分大小写），没有匹配显示 `tree.noMatch`；↑↓ / Enter 在搜索框里照常作用于列表，Esc 有字时先清字、再按才关对话框。④光标停在一条用户消息上时，列表下方一行提示（`session-tree-discard`，`tree.discard`）：回到它之前有几轮会离开当前对话；0 轮不出现。

**会话开关菜单与模型预设**（S4，`features/session-toggles/`，语义和实测见 `docs/architecture/session-toggles.md`）：
- ①**入口与外观**：工具行当前文件夹（`composer-folder`）右边一颗滑杆图标胶囊（2026-10-22 仓库所有者定；`.ui-chip.tg-button`，`toggles.button`，`toggles-button`），点开 `Popover`（宽度要够英文里浏览器窗口那一行不被挤成一窄条）：每行名称在左、“本会话”标记和 `ui/Switch` 在右：Skill 清单、扩展上下文、电脑操作、顾问模型；浏览器窗口是“可见 / 后台”两段 `ui/Segmented` sm，同一种排法。没有顶部说明行和每行灰字，只有扩展上下文有后果要交代，放进悬停 `toggles.extendedContext.hint`（电脑操作的后果在开启前的确认里说）。快速 / 慢速和 Prewalk 不在这个菜单里，在模型选择器（Prewalk 见⑦）。
- ②**状态**：`TaskState.sessionToggles`（`{skillful, extendedContext, computer, advisor, browser, prewalk}`，`null` = 本会话没动过）由 `TspRunner` 在每次文档变化时读新出现的状态 toast（`statusNotes` + `omp.toast.status`）用 `parseToggleToast`（`shared/omp-output/toggles.ts`，omp 18.12.5 原文入测）解析，所以用户自己敲的 `/skillful` 也同步；新进程从头开始。没动过的开关显示 `omp config list --json` 的配置默认值（`skillful`、`extendedContext`、`computer.enabled`、`advisor.enabled`、`browser.headless`、`prewalk.enabled`），读不到时按关显示、不画圆点。
- ③**标记**：值来自本会话的命令时，行上有 accent `Badge` `toggles.session`（“本会话”）；和配置默认值不同时名称后一个 accent 圆点（`role="img"`，`aria-label` = `toggles.differs`），胶囊角上同样亮一个圆点（`data-differs`）。
- ④**电脑操作**：开启（菜单里点开关或 `/computer on`）先把同一个 `Popover` 换成确认页（`kind="confirm"`：`toggles.computerConfirmTitle` / `…Body`：模型将能看屏幕、操作键鼠，只对本会话生效；`common.cancel` + 主按钮 `toggles.computerConfirmYes`），确认才发命令；关闭直接执行。
- ⑤**动作**一律是封闭的 `TaskCommand`（`toggle` / `browserMode` / `prewalk` / `modelPreset`，主进程拼成 `/skillful on` 等文本，渲染进程不发自由文本）经 `runTaskCommand`；同一时间只有一条命令在飞（其余控件禁用）；omp 的拒绝作为错误 toast 原文显示，认不出的回话（用法提示、预设保存结果）作为 info toast 原文显示。
- ⑥**斜杠命令**（都由 studio 接管）：`/skillful` `/extended-context` `/computer` `/advisor` `/browser` 不带参数（或 `status`）打开这个菜单，`/prewalk` 不带参数（或 `status`）打开模型选择器；带 `on` / `off`（`/browser visible|headless`、`/prewalk restart|off`）直接执行，`/computer on` 先弹确认；参数不认识抛出用法（草稿放回输入框）。`/modelpreset`（无参数 / `list`）打开模型选择器；`/modelpreset save|switch|delete <名字>` 直接执行：`save` 的新名字只许字母、数字和 `. _ -`（`presetNameUsable`）；`switch` / `delete` 的已有名字可以含空格（`presetRefUsable`，见下）。
