# 4.20 Provider 与订阅（设置页的一节；登录流）

代码 `features/settings/`：`ProvidersSection.tsx`（页面）、`ProviderRow.tsx`（一行）、`ProviderPickDialog.tsx`（连接提供商）、`ProviderFlowDialog.tsx` + `ProviderPanels.tsx`（登录 / 填 key / 选账号 / 失败）、`CustomProviders.tsx` + `CustomProviderForm.tsx` + `CustomModelList.tsx` + `ModelPicker.tsx`（自定义提供商）、`RowMenu.tsx`（⋯），分组规则和卡片上的账号名 `src/shared/ui/provider-list.ts`，样式 `providers.css`、`custom-providers.css`，文案 `login.*`、`custom.*`。omp 列出 80 多个提供商，**没连接的不在页面上铺开**（`direction-3.2.md` §7 第 3 项）。

- **数据**：`accounts-store.ts` 一次读 `get_login_providers`（提供商列表）、studio 存了 key 的提供商、模型列表，再对已认证的提供商逐个读 `get_logout_accounts`（账号）；有缓存先显示，进入时后台刷新；登录、退出、改 key 之后强制重读。读取失败是 error `Notice` `login.loadFailed`；后台刷新失败时保留上次结果，上面一条 warning `Notice` `login.refreshFailed`。
- **分组**（`splitProviders`）：**已连接** = omp 认为已认证（登录过、环境变量或配置里有凭据）或 studio 存了 key 的；其余是"没连接"。两组内都保持 omp 的顺序。
- **页面自上而下**：分组 `已连接`（`login.connected`，不带个数），标题行右侧 `连接 provider…`（`login.connect`，sm 次要按钮带 `+`，`providers-connect`；还在读取或没有未连接的提供商时禁用；放在分组标题行、和"自定义提供商"的按钮同一种位置，仓库所有者定，2026-10-24）：每个一行；一个都没有时一句 `login.connected.empty`。分组 `自定义提供商`（见下）。没有"其他提供商"分组：没连接的提供商的入口只有 `连接 provider…` 的选择对话框（仓库所有者定，2026-10-23）。
- **卡片**（`ProviderRow.tsx`，`ui/ListRow` 放进 `.ui-cards`，`provider-<id>`；网格、尺寸见 §4.23 SectionHead / Row / ListRow）：已连接和自定义提供商都排成卡片网格，同一行卡片等高（一行一个太占地方，仓库所有者定，2026-10-22）。**卡片两行**（仓库所有者定，2026-10-29；内边距加大是所有者 2026-10-30 嫌难看）：左侧方图标块跨两行（provider 的单色 logo、`currentColor` 跟主题：`ProviderLogo.tsx`，图形拷自 LobeHub Icons，MIT，许可证随安装包放进 `resources/licenses/`；没有 logo 的写名称首字母）；第一行是名称（单行省略）、靠右的图标按钮（见下"按钮"）；第二行从名称下面开始：状态 `Badge` 在前，元信息跟在后面（单行省略，可以伸到动作下面）。900 宽中英文不越界。选择对话框里同一个 `ProviderRow` 仍是一行（小一号图标块，名称下面同样是徽标 + 元信息，文字按钮并排）。

| 状态（按顺序取第一条命中的；徽标按凭据来源分，环境变量和 key 不写"已登录"，仓库所有者定，2026-10-24） | 徽标 | 元信息 |
|---|---|---|
| 有 OAuth 账号（`type: "oauth"`） | `已登录`（success） | 账号名；多个时 `第一个 +N` |
| 只有 API key 账号（`type: "api_key"`，设置页或终端 `/login` 粘贴的） | `已设置 key`（success） | 账号名（omp 起的 `API key #<n>` 不写，见下） |
| omp 已认证、凭据库里没有账号（环境变量、agent 目录的 `.env`、`models.yml` 的 `apiKey`） | `已配置`（success） | `环境变量 · <变量名>`（已知时） |
| omp 报不可用 | `当前不可用` | — |
| 其余 | 无（选择对话框里整张列表都是未连接的） | 无（多步登录也不写，`登录` 按钮已说明） |

- **账号名是内部编号时不写**（仓库所有者定，2026-11-11；`accountSummary`）：UUID、长串十六进制、omp 起的 `OAuth credential #<n>` / `API key #<n>` 用户看了没信息，元信息位置空着、只留徽标；邮箱、用户名照写。多个账号时取第一个能读的，`+N` 是其余账号的个数。
- **按钮**：能填 key 的（`provider-keys.ts` 的 `acceptsApiKey`：有已知环境变量名，或登录方式就是粘贴 key）有 `设置 API key`（已有 `api_key` 账号时是 `更换 key`），打开 key 对话框；有账号的有退出（有 OAuth 账号时是 `退出登录`，只有 key 账号时是 `清除 key`）——只有一个账号时直接 `logout`，多个时打开对话框选账号（key 是一条 `API key #<n>` 账号）；只有环境变量 / 配置文件的没有退出（要去掉就改 `.env` 或 `models.yml`，自定义提供商分组标题旁有 `打开 .env`）；没登录的 OAuth 类有 `登录`；多步登录的（`loginKind` = `terminal`，omp 的 rpc `login` 直接拒绝）也是 `登录`（`provider-terminal-login-<id>`），打开流程对话框的"应用内登录"（下表）；已有 OAuth 账号、登录方式是 OAuth 或多步登录的有 `添加账号`（`login.addAccount`，`provider-add-account-<id>`，打开同一个登录 / 应用内登录对话框，换一个账号登录就多一个账号）。
  - **卡片上是图标按钮**，和自定义提供商的卡片一致（仓库所有者定，2026-11-11）：自左向右 `添加账号`（人 + 加号）· `设置 API key` / `更换 key`（钥匙，`provider-key-<id>`）· `登录`（箭头进门）或退出（箭头出门，`provider-signout-<id>`）；读屏名和悬停就是上面的文字。有哪个画哪个，一起靠右，不留空位（仓库所有者定，2026-11-11）。没有 ⋯。
  - 选择对话框里是 sm 次要文字按钮并排（`设置 API key` 在前），直接选连接方式。登录方式按实测分类（omp 的 `get_login_providers` 没有这个字段；`src/shared/provider-login.ts`，`docs/architecture/login.md`），表里没有的按 OAuth 处理。
- **连接提供商…**（`ProviderPickDialog.tsx`，`ui/Dialog` md，`provider-pick`）：标题 `login.connect.title`，没有说明；顶上搜索框（`login.search`，打开时焦点在它上，`provider-search`），按名称和 id 过滤，每个词都要命中；下面是未连接提供商的行（同上面的行，限高后滚动），没有匹配时 `login.noMatch`；页脚只有 `关闭`。点行里的按钮，选择对话框换成流程对话框（同一时间只有一个对话框）。
- **流程对话框**（`ProviderFlowDialog.tsx`，`ui/Dialog` md，标题是提供商名，`provider-flow-<id>`）：从选择对话框进来、且不在登录进行中时，页脚左侧有 quiet `返回`，回到选择对话框。五种内容：

| 内容 | 正文 | 页脚 |
|---|---|---|
| 登录（OAuth，或经 omp 粘贴 key） | 一打开就发 `login`。先是 `login.opening`；收到 `open_url` 时主进程已经用系统浏览器打开它（只放行 http/https），对话框里显示 `login.fallback` + 只读等宽的 `launchUrl ?? url` + 复制图标按钮（复制后变成对勾，§2.6）+ `login.reopen`；有 `instructions` 时作为淡色文字；omp 的进度提示按到达顺序一行一条全部保留（`login-progress`），按 `info` / `warning` / `error` 着色；omp 要输入（授权码等）时出现输入框（标题和占位用 omp 给的，没有占位时 `login.pasteCode`；登录方式是粘贴 key 的遮住），Enter 提交；omp 撤销这个输入（超时 / 取消）时输入框和 `提交` 一起收起，进度保留；不显示输入超时倒计时 | `取消`（同时取消 omp 的登录）；有输入框时加主按钮 `提交` |
| 填 API key | `API key` 字段（等宽、遮住），已经有 key 时占位 `login.apiKey.keepStored`（不分 .env / 凭据库），没有 key 时没有占位；默认没有说明；omp 实际用的 key 变量（主名或 fallback，如 `HF_TOKEN`）写在 agent 目录 `.env` 里时说明 `login.apiKey.noteEnvFile` 并改写那一行；在系统环境变量里时说明 `login.apiKey.noteSystem`（这里存的不生效）。说明和列表一起读好，打开对话框时就是最终文字，不闪。key 经 `omp auth import` 存进 omp 自己的凭据库，终端版 omp 也用它，清除就退出登录这个 provider。**Tavily 另有 `备用 key` 字段**：等宽多行 `Textarea`（`provider-backup-keys`），每行一个，说明 `login.apiKey.backup.note`（当前 key 用完时按顺序换下一个，omp 里的扩展换，见 `docs/architecture/login.md`「Tavily 备用 key」）；key 只进不出，已存的只在占位里说个数（`login.apiKey.backup.keep`）；两个字段填了哪个存哪个，都空时 `保存` 禁用；已存备用 key 时页脚左侧有 quiet `清除备用 key`（`provider-backup-clear`）。下面 `每个 key 的用量`（`provider-key-usage`）：打开对话框时查一次，当前 key + 每个备用 key 各一行（`provider-key-usage-row`），样式同"用量"对话框的额度行（`.uq-limit`）：左上 key 名，右上 `已用 / 上限`，进度条 + 剩余百分比；用尽、key 无效红字，查不到写用量未知；还有查询中、一个 key 都没有、整体失败三种整块状态 | `取消` + 主按钮 `保存` |
| 选账号退出 | `login.chooseAccount` + 每个账号一行按钮（账号名 + 徽标 `login.accountActive`（`LogoutAccount.active` 为 true 时） + 淡色详情），点了就 `logout` 那个账号 | `取消` |
| 应用内登录（`loginKind` = `terminal`） | 一打开就让主进程起一个临时的 omp 跑 `/login <provider>`（`startTerminalLogin`，`docs/architecture/login.md`「应用内登录」）。正文（`TerminalLoginBody.tsx`，`terminal-login`）只画那个 omp 的登录窗（过程区的 TSP 渲染器，只画 layer 里的 `omp.overlay.login`，摊平成对话框正文：没有遮罩、阴影和 omp 自带的标题）：企业域名 / 区域 / 授权码等输入框、设备码（`omp.login.code`，点一下复制）、授权链接、`Open sign-in page` / `Copy` / `Continue` 按钮都是 omp 发来的节点，英文是 omp 的原文，不汉化（过程区规则）；链接走系统浏览器（`openExternal`，只放行 http / https）；omp 起来之前是淡色 `login.terminal.starting`。omp 自己的 Cancel 按钮不画（`display: none`），页脚的 `取消` 是同一件事 | `取消`（`provider-terminal-cancel`，关临时 omp）；Esc、× 同样 |
| 失败 | 只一行：红字写原因（omp 的原话，应用内登录失败时是 `Error: Login failed:` 后面那句）；rpc 登录的原话里有 secret / terminal（omp 升级后新增、`provider-login.ts` 表里还没有的多步登录 provider）时换成 `login.terminalOnly` | `关闭` + 主按钮：上面那种情形是 `在应用内登录`（`provider-terminal-here`，改走应用内登录），其余是 `重试`（重新走同一个动作，跑过应用内登录的重试它） |

流程对话框成功（登录完成、key 已保存、已退出）后关闭并重读列表；登录结果是 `cancelled`（含应用内登录里点 omp 自己的取消）时直接关闭，不报错。应用内登录的临时 omp 在结果出来、对话框换内容之前已经关掉；对话框关闭（取消、Esc、×）即结束进程。

- **自定义提供商**（`CustomProviders.tsx`，`custom-providers`）：omp 的 `models.yml` 里 `providers.*` 的列表，直接读写 omp 的文件（`docs/architecture/custom-models.md`）。分组标题 `自定义提供商`（带个数），右侧 `刷新模型`（quiet sm）· ⋯（`custom-files`，菜单两项：`打开 .env`（omp agent 目录的 `.env`，环境变量形式的 key 常写在这里；没有这个文件时打开目录）、`打开 models.yml`；标题行只留一个文字按钮和一个主动作）+ `添加 provider...`（sm，读取中或读取失败时禁用）。分组标题右侧的按钮间距见 `.ui-section-actions`。读取失败是 error `Notice`；没有时一句 `还没有自定义提供商`。
- **卡片三行**（仓库所有者定，2026-11-11）：ID；端点（Base URL 去掉协议和末尾 `/`，等宽、放不下省略，完整地址在悬停里）；模型，一个模型一个小标签，只排一行，放不下的收成 `+N`，悬停列出全部（`ModelChips.tsx`，`custom-models-<id>`；没有模型、靠运行时发现的写 `运行时发现模型`）。key 来源和接口类型不上卡片，在编辑里看。图标按第一个认得出品牌的模型画 LobeHub 单色 logo（`gpt-*` → OpenAI、`claude-*` → Claude、`gemini-*` → Gemini、`grok-*` → Grok 等，`ProviderLogo.tsx` 的 `modelLogo`；自定义 provider 的名字是自己起的，看不出是哪家），认不出时首字母。动作两个图标按钮，一直显示：铅笔 `编辑`（`custom-edit-<id>`）、垃圾桶 `删除`（`custom-delete-<id>`，悬停 / 聚焦变红；先 `ConfirmDialog` danger，正文写明只去掉这个提供商、留一份 `models.yml.bak`，key 在 `.env` 里又没别人用时那一行也删、留 `.env.bak`）。
- **拉取失败标在卡片上**（仓库所有者要求，2026-10-24）：编辑对话框里用文件里的连接（Base URL、接口类型、key 都没改，或改了之后保存）拉取模型失败，ID 后面一个 error 徽标（`custom-fetch-failed-<id>`）：`key 无效`（401/403、key 不合法）、`地址不通`（连不上、超时、404、Base URL 不合法），其余 `拉取失败`；完整原因在悬停里。接口类型不支持拉取、key 是命令时不记。同样的连接再拉取成功、保存时改了连接（没再拉取）、删掉 provider 都会去掉；拉取用的是改过又没保存的连接时，卡片不变。只在内存里（`custom-models-store.ts`），重启后没有。
- **缓存不命中标在卡片上**（仓库所有者要求，2026-10-29）：有模型走 `anthropic-messages`（provider 这一级或模型自己的 `api`）、条目里没写 `auth` 的自定义提供商，ID 后面一个 warning 徽标 `缓存不命中`（`custom-oauth-shaping-<id>`），悬停写原因和修法（点「编辑」后保存一次）。保存时写上 `auth: apiKey`，徽标随之消失；覆盖内置 provider 的条目不显示。原因见 `docs/architecture/custom-models.md`「Anthropic 格式要写 `auth: apiKey`」。
- **只覆盖内置 provider 的条目**（仓库所有者要求，2026-10-24）：没有模型也没有 `discovery` 的条目（如 `anthropic` 下只有 `modelOverrides`）不是自定义提供商，是对 omp 内置同名 provider 的覆盖。卡片没有端点一行，模型行列写了能力参数的覆盖项。和别的卡片一样铅笔 + 垃圾桶，编辑打开覆盖对话框（`ProviderOverrideDialog.tsx`，`ui/Dialog` xl、`.cp-dialog` 同样固定大小，`custom-override-dialog`，标题 `编辑 {id}`）：上面是 API key（分段：原来直接填或命令取 key 时多一个 `保持不变`，再是 `直接填` / `环境变量` / `不设置`，下面同一个 `KeyFields`，悬停说明 `优先于登录的订阅`），下面是和添加 / 编辑对话框同一个模型表（`CustomModelList`，不带拉取和自动发现）：行是 omp 现在列出的这个 provider 的模型，文件里有覆盖项的勾着、排在前面，也能手动添加；没写的格子显示 omp 现在用的值。保存只改 `apiKey` 和各覆盖项的四个能力参数，覆盖项里别的键（`name`、`compat`……）和条目里别的键原样；取消勾选 = 去掉这个模型的能力参数，空了的覆盖项、`modelOverrides`、条目依次删掉。
- **添加 / 编辑对话框**（`CustomProviderForm.tsx`，`ui/Dialog` xl，标题 `添加自定义提供商` / `编辑 {id}`）：
  - **高度跟内容走、最高 760px**（`.cp-dialog`；还没有模型时不留空白，仓库所有者定，2026-11-11），连接信息在上，模型表按行数长，到顶后在表里滚动；顶边钉在窗口上方 48px、只往下长（不居中，高度变化时指针下的控件不跳），拉取后的挑选浮层开着时撑到最高。
  - 连接信息两栏：左栏上下排 ID（编辑时禁用）、接口类型（`Select`：OpenAI Chat Completions / OpenAI Responses / Anthropic Messages / Google Gemini / Azure OpenAI / Amazon Bedrock，选项第二行小字 `custom.api.<api>` 写常见服务；选 Gemini / Azure / Bedrock 时 Base URL 占位换成它们的地址格式）、Base URL，右栏是 API key 占满这三行（key 那格高，按行填会在 Base URL 下面空出一大块）；窄窗口时一栏，按 ID、接口类型、Base URL、key 的顺序。
